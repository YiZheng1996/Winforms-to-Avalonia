## 3. 产品目标

建设一套可以通过“代码模板 + 配置”快速派生具体试验台项目的 Avalonia 上位机框架。第一版优先形成操作员可验证的业务闭环：

    登录
      → 配置产品与配方
      → 本地手工创建任务
      → 选择已发布配方
      → 启动前检查
      → Simulation 或 Hardware 执行
      → 保存试验记录与项点结果
      → 通过 Excel 模板生成报表
      → 本地查询和导出

框架必须允许具体项目通过配置更换品牌、产品、型号、配方、项点、参数、设备档案、点位和报表模板；无法通过配置表达的具体试验算法通过明确的代码扩展点实现，不允许在运行时生成、编译或执行任意 C#。

## 4. 已确定的产品边界

### 4.1 必须具备

- .NET 8 + Avalonia 桌面应用。
- Windows 开发验证和目标 UOS 发布能力；两者必须分别记录验证证据。
- 本地 SQLite 业务数据和身份权限数据。
- Simulation 与 Hardware 两种设备模式。
- 本地手工创建任务。
- 产品类型、产品型号、试验项、参数定义和配方版本管理。
- 试验执行、记录、项点结果、日志和 Excel 报表生成。
- 登录、角色、权限、危险操作确认和设备写入安全门。
- 1440×900 与 1920×1080 两种分辨率的自适应界面。

### 4.2 明确不包含

- PressureTestApp 的在线、离线、Excel 三业务模式。
- EPE/API、心跳、远程任务下载、远程上传和服务器任务同步。
- Excel 作为任务来源、运行参数来源或配方导入来源。
- 硬件连接失败后自动切换 Simulation。
- Legacy 动态创建、移动、删除或编译试验类源码。
- 以旧 WinForms 页面一比一复刻作为新框架验收标准。
- 在第一版引入独立 Gateway Host、OPC UA 中转或分布式服务作为业务闭环前置条件。

- App 只通过用例和接口驱动业务，不直接执行 SQL、PLC 写入或报表文件操作。
- 组合根创建具体实现；View 和 ViewModel 不通过全局服务定位器获取依赖。
- 第一版设备运行时在应用进程内工作；只有出现明确的部署、隔离或多进程需求后才评估独立 Host。

## 6. 配置与数据职责

### 6.1 文件配置

| 文件 | 内容 | 是否允许 UI 修改 |
| --- | --- | --- |
| config\app.json | 系统名称、品牌、语言、模块开关、默认路径 | 仅管理员可修改受支持字段 |
| config\device.json | DeviceMode、硬件档案、轮询和超时 | 仅维护权限；活动试验中禁止修改 |
| config\points.json | 点位代码、协议、地址、类型、缩放、读写和风险级别 | 第一版通过受控配置维护 |
| config\simulation.json | 仿真初值、变化规则、故障注入场景 | 仅 Simulation 使用 |
| assets\report-templates\ | Excel 报表模板 | 通过配方版本关联，不作为输入数据源 |

所有配置必须包含 schemaVersion。配置无效时启动进入明确 Faulted 状态并显示诊断，不得静默改为默认值，也不得切换到 Simulation。配置保存采用临时文件、校验、原子替换和可恢复前一版本。

### 6.2 SQLite 数据

SQLite 保存：

- 用户、角色、权限和审计；
- 产品类型、产品型号；
- 试验项定义、参数定义；
- 配方版本、配方项点、参数值；
- 本地任务；
- 试验记录和项点结果；
- 报表生成记录和运行日志索引。

核心业务不得继续使用一个通用 management_records + JSON 表承载。正式实体使用可查询、可约束、可迁移的独立表和外键。

## 7. 设备运行模式

### 7.1 模式定义

| 模式 | 行为 |
| --- | --- |
| Simulation | 只创建仿真设备运行时；不连接真实设备；所有界面和记录必须显示仿真标识 |
| Hardware | 只创建配置指定的真实设备运行时；连接失败进入断开或故障状态并阻断试验 |

DeviceMode 是启动配置，不是普通操作员可随意切换的页面按钮。切换模式要求无活动试验、具备维护权限并重新初始化设备运行时。

### 7.2 禁止自动回退

Hardware 初始化、连接、轮询或写入失败时：

1. 保留 Hardware 模式。
2. 标记具体设备和点位质量。
3. 阻断依赖该设备的启动或后续动作。
4. 记录结构化日志和审计信息。
5. 允许有权限的用户重连或退出。
6. 不得创建 Simulation 运行时，不得伪造成功数据。

### 7.3 写入安全链

所有设备写入统一经过：

    权限
      → 当前模式必须为 Hardware
      → 连接和点位质量
      → 活动任务与运行状态
      → 业务联锁
      → 风险级别确认
      → 写入
      → 回读或结果确认
      → 审计

Simulation 可以执行同一业务命令，但只能写入仿真状态。高风险动作在两种模式都保留明确标识，Hardware 额外要求确认和回读。界面不得直接调用协议库写方法。

## 8. 领域模型

取消 step_parameter、step_binding、step_run 和 measurement 设计。第一版正式模型如下：

| 实体 | 主要职责 | 关键关系与约束 |
| --- | --- | --- |
| ProductType | 产品类型主数据 | 类型代码唯一；停用后不可新建任务 |
| ProductModel | 产品型号主数据 | 必须属于一个 ProductType；型号代码在产品类型内唯一 |
| TestItemDefinition | 可复用试验项定义 | 项点代码唯一；定义执行器代码、显示名称、结果类型和启用状态 |
| ParameterDefinition | 试验项参数定义 | 属于一个 TestItemDefinition；定义类型、单位、必填、范围、精度和枚举 |
| RecipeVersion | 某产品型号的一版配方 | 属于一个 ProductModel；版本号在型号内唯一；Draft、Published、Retired |
| RecipeItem | 配方包含的项点 | 关联 RecipeVersion 与 TestItemDefinition；顺序在配方内唯一 |
| RecipeParameterValue | 配方项点参数值 | 关联 RecipeItem 与 ParameterDefinition；值必须通过定义校验 |
| TestTask | 本地手工任务 | 关联 ProductModel 和已发布 RecipeVersion；保存产品标识和任务状态 |
| TestRecord | 一次实际执行记录 | 关联任务；快照配方版本、模式、操作员、时间和总体结论 |
| TestItemResult | 单个项点执行结果 | 关联 TestRecord 和 RecipeItem；保存结论、摘要值、异常和时间 |

### 8.1 配方规则

- Draft 可以编辑。
- Published 一经使用即不可原地修改；修改必须复制为新版本。
- Retired 不可用于新任务，但历史记录继续可读。
- 任务只能选择与产品型号一致的 Published 配方。
- 启动试验时固化配方快照；运行中修改主数据不得影响当前记录。
- 参数值由 ParameterDefinition 校验，不能在工艺监控页或项点定义页临时覆盖。

### 8.2 任务和记录规则

建议的第一版状态：

| 对象 | 状态 |
| --- | --- |
| TestTask | Draft、Ready、Running、Completed、Failed、Cancelled |
| TestRecord | Running、Completed、Failed、Aborted |
| TestItemResult | Pending、Running、Passed、Failed、Skipped、Aborted |

TestTask 是待执行工作，TestRecord 是一次实际执行，两者不得合并。重做产生新的 TestRecord，不覆盖上一条结果。

measurement 不作为独立领域表。第一版在 TestItemResult 中保存判定所需的摘要结果和报表字段。若具体项目需要高频曲线或大体量采样，另行设计受控的时序存储，不把该需求预先塞入通用模型。

## 9. 第一版业务闭环

### 9.1 管理员准备

1. 创建产品类型。
2. 创建产品型号。
3. 创建试验项定义。
4. 为试验项创建参数定义。
5. 创建配方草稿。
6. 选择配方项点、设置顺序并填写参数值。
7. 选择报表模板。
8. 校验并发布配方版本。

### 9.2 操作员执行

1. 登录。
2. 本地手工创建任务。
3. 选择产品类型、产品型号和已发布配方。
4. 填写本次产品标识字段。
5. 执行设备、联锁和配置预检。
6. 启动试验并逐项执行。
7. 保存项点结果和总体记录。
8. 通过 Excel 模板生成报表。
9. 在数据与报表页查询、打开和导出。

### 9.3 Excel 边界

- Excel 模板只负责报表版式和输出占位。
- 程序把已保存的 TestRecord、TestItemResult 和配方快照写入模板。
- Excel 不创建任务、不覆盖配方、不提供运行参数、不决定判定结果。
- 报表文件生成失败不回滚已经提交的试验记录；失败状态可重试并有日志。
- 模板、输出目录、文件名规则和模板版本必须可追踪。

## 10. UI 信息架构

### 10.1 应用外壳

应用外壳包含：

- 顶栏：系统名称、当前设备模式、总体连接状态、当前任务、登录用户；
- 左侧主导航；
- 主内容区；
- 底部状态区：时间、数据库、设备、日志摘要和版本；
- 全局通知区：成功、警告、错误和需要确认的危险动作。

DeviceMode 和 Hardware 连接失败必须在所有业务页面持续可见，不能只显示在设置页。

### 10.2 主页面

| 页面 | 核心职责 | 明确不承担 |
| --- | --- | --- |
| 登录 | 认证、锁定提示、首次改密 | 设备模式选择 |
| 运行总览 | 当前模式、设备健康、活动任务、告警和快捷入口 | 编辑配方参数 |
| 任务管理 | 本地创建、编辑、取消和选择任务 | 从 Excel 或服务器下载任务 |
| 试验执行 | 预检、项点进度、执行控制、结果和异常恢复 | 编辑参数定义或配方 |
| 工艺监控 | 实时值、状态、趋势和受控手动动作 | 修改运行参数、维护项点定义 |
| 数据与报表 | 查询记录、查看项点结果、生成或重试报表、导出 | 修改历史试验结果 |
| 配方中心 | 产品类型、产品型号、项点定义、参数定义、配方版本 | 运行实时控制 |
| 设备与校准 | 设备档案、点位、连接诊断、校准和回读 | 自动切换 Simulation |
| 系统管理 | 用户、角色、权限、应用配置 | 业务试验执行 |
| 日志诊断 | 日志、审计、故障上下文和导出 | 直接绕过故障继续运行 |

配方中心内部使用独立子页面，不再设置旧“试验项点配置”和“试验参数”两个混合页面：

1. 产品类型。
2. 产品型号。
3. 试验项定义。
4. 参数定义。
5. 配方版本列表。
6. 配方版本编辑器：项点顺序与参数值。

### 10.3 UI 详细规格门

进入 UI 编码前，每个页面必须完成以下内容：

1. 信息架构和进入路径。
2. 区域布局和控件层级。
3. 字段名称、类型、默认值、是否必填和数据来源。
4. 命令、二次确认、取消、重入和异步忙碌状态。
5. 页面可见权限、命令执行权限和仓储二次鉴权。
6. 输入校验、跨字段校验和服务端或设备错误映射。
7. 首次使用空态、无查询结果、无权限、加载中、部分失败和完全故障状态。
8. 键盘焦点、触控目标、可访问名称和快捷键冲突。
9. 1440×900 线框。
10. 1920×1080 线框。
11. ViewModel 行为测试和 Headless 验收场景。

优先级：

- P0：登录、应用外壳、任务管理、试验执行。
- P1：配方中心、数据与报表、运行总览。
- P2：工艺监控、设备与校准、系统管理、日志诊断。

P0 规格未锁定前，不开始主业务页面编码。

### 10.4 双分辨率布局约束

| 项目 | 1440×900 | 1920×1080 |
| --- | --- | --- |
| 布局模式 | Compact | Wide |
| 主导航 | 保留图标与短标题，宽度受控 | 可展示完整标题和辅助状态 |
| 编辑页 | 主列表 + 抽屉或上下文编辑区 | 主列表 + 固定详情编辑区 |
| 试验执行 | 关键状态和操作优先，次要诊断折叠 | 任务、项点、实时状态并列 |
| 表格列 | 保留关键列，次要信息进入详情 | 展示完整常用列 |
| 滚动 | 主流程不得依赖水平滚动 | 充分利用宽度，避免无意义留白 |

两种分辨率都必须满足：

- 主操作按钮不被遮挡。
- 错误信息和模式标识可见。
- 不使用绝对坐标堆叠普通控件。
- 页面允许纵向滚动，但主流程不因横向滚动而丢失上下文。
- 对话框不超出工作区，内容超长时内部滚动。
- 真实 Headless 布局行为和人工线框检查同时通过，截图不能作为唯一验收。

| SQLite 版本、完整性检查、事务和原子初始化 | 复用模式，重新建立正式业务 schema |
| ConfigLocator 和配置原子保存 | 重命名并迁移为通用配置服务 |
| S7、Modbus 仅读传输 | 复用经过验证的协议读取部分；写入另建安全接口 |
| 日志和 Headless 测试宿主 | 选择性迁移 |
| MainWindowViewModel、ManagementViewModel | 不迁移实现；按新页面和用例重建 |
| TestBenchStateMachine | 不直接迁移；按任务、运行和记录状态重新建模 |
| ReadOnlyGatewayRuntime、Gateway Host | 第一版不迁移 |
| B11、P2 五点、PressureAdjustmentWorkflow | 仅作具体项目示例或 Legacy 证据 |
| management_records 通用业务表 | 不迁移为新业务存储 |
| Phase E、Legacy coverage、cutover 文档 | 保留在旧线，不作为新线完成证据 |

每个被复用文件在迁移前必须登记来源、目标所有者、保留行为、删除的旧耦合和对应测试。不得整目录复制后再逐步清理。

## 14. 第一版验收口径

第一版完成必须同时满足：

1. 新主线解决方案可独立构建，不引用 PressureTestApp、WinForms 或 XXX.TestBench.Uos 项目。
2. 登录、权限和 SQLite 持久化重启回读通过。
3. 产品、型号、项点、参数和配方版本全链路可用。
4. 本地任务可创建并只能选择匹配型号的已发布配方。
5. Simulation 完成完整业务闭环且所有记录带仿真标识。
6. Hardware 连接失败时阻断运行且不自动回退。
7. 写入经过权限、联锁、确认、回读和审计。
8. 试验记录与项点结果不可被普通操作员静默修改。
9. Excel 报表从已保存数据生成，Excel 不参与任务或运行参数输入。
10. P0/P1 页面在 1440×900 和 1920×1080 下无关键遮挡或水平滚动依赖。
11. Core、ViewModel、Headless、SQLite、Simulation 和报表测试分别通过。
12. Windows、UOS、Simulation、Hardware 和现场验证状态分别标注，不互相替代。

## 15. 编码前仍需逐项确认的问题

以下问题不会改变“新建主线”的决定，但会影响数据字段、UI 和命令合同，必须在阶段 1 逐项确认：

1. 本地任务编号是自动生成、人工输入，还是两者组合；是否允许重复。
2. 本次产品标识需要哪些字段：产品编号、车号、批次号、工位号、备注中的哪些为通用必填。
3. 产品类型和型号停用后，历史任务、配方和记录的显示规则。
4. 参数支持的数据类型、单位、精度、枚举、上下限和表达式范围。
5. 试验项执行器的扩展方式，以及第一个可运行的代表性项点。
6. 配方版本号格式、发布审批人、是否需要双人复核。
7. 项点跳过、重做、中止和失败后继续的具体规则。
8. TestItemResult 需要保存的通用摘要字段，以及曲线或高频数据是否属于第一版。
9. Hardware 第一版必须支持的设备、协议、地址和写入动作。
10. 报表模板是一型号一份、一配方版本一份，还是允许多个模板；输出命名和目录规则。
11. 系统内置角色及其默认权限。
12. 工艺监控和设备校准是否所有派生项目都启用，还是由模块配置控制。

在这些问题明确并形成 UI 详细规格前，不把页面占位、硬编码示例或 Legacy 字段当成最终实现。
