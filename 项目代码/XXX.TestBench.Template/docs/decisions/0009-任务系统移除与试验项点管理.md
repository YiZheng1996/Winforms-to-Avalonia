# ADR-0009：移除任务系统，改为试验项点管理与项点配置

- 日期：2026-09-03
- 状态：已接受（已实现）
- 目标项目：XXX.TestBench.Template

## 背景

用户确认本产品不存在“任务”概念：主数据只有 产品类型 → 产品型号 → 自动试验项点名称。
原模板中的 任务创建/就绪/执行 闭环是模板假设，不符合产品语义。

## 决策

1. 删除任务系统：TestTask/TaskState/TaskService/ITaskRepository/TaskRepository、任务管理页、test_tasks 表。
2. 新增两级管理：
   - 试验项点管理：项点归属产品类型，包含数据库自动生成的项点编号 `Id`、项点名称、关联逻辑类（编译期注册 ITestItemExecutor 代码）、判定类型、启用、排序。
   - 项点配置：为产品型号从其产品类型的启用项点中选择并按顺序编排自动试验序列。
3. 执行直接面向产品型号：启动时固化 参数快照 + 项点序列快照 并创建试验记录（R-yyyyMMdd-xxxxxx）；逐项执行；报表按记录编号与固化序列输出。
4. 权限：PermissionCode.ManageTasks(2) 改名 ManageTestPoints(2)（数值不变，兼容历史数据库）；Operator 种子角色不再授予；v4 迁移回收旧库非管理员角色的该权限。
5. 数据迁移（schema v4）保留旧试验记录（task_number 映射为 record_number），删除任务与旧项点结果关联。
6. 产品类型、产品型号和试验项点不再手工维护业务代码；业务关联统一使用 `ProductType.Id`、`ProductModel.Id`、`TestItemPoint.Id` 及对应外键。schema v4 的旧 `code` 列暂保留兼容，应用层不读取或匹配。

## 影响

- 参数管理页从 3 个标签扩展为 5 个：产品类型 / 产品型号 / 试验项点 / 项点配置 / 试验参数。
- 运行总览/设备校准/工艺监控改读活动试验记录。
- 报表“任务编号”改为“记录编号”。

## 不做

- 不引入运行时无代码设计器或动态逻辑；关联逻辑类只能选编译期注册执行器。
- 不迁移真实项目全部项点与参数（仍为模板示例链路）。
