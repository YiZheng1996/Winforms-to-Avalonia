# ADR-0011：系统管理用户角色权限

## 状态

已采纳并实施。

## 背景

系统需要按角色配置权限，用户账号与角色关联。原系统管理页面只有只读用户、角色列表，不能完成账号维护和权限变更；同时页面隐藏或禁用不能替代业务层授权校验。

## 决策

1. 保留一个“系统管理”入口，页面内分为“用户管理”和“角色权限”两个标签页。拥有任一对应权限的用户可以进入页面，标签页和写操作按权限分别显示或禁用。
2. 采用轻量 RBAC：一个用户关联一个角色，一个角色拥有多个权限。用户登录时读取角色权限并生成会话上下文，角色或用户变更在相关用户下次登录时生效。
3. 新增 `ManageRoles` 权限；`ManageUsers` 只负责账号，`ManageRoles` 负责自定义角色和权限矩阵。`GenerateReports` 自动依赖 `ViewRecords`，`CalibrateDevices` 自动依赖 `ManageDevices`。
4. Administrator、Operator、Maintenance 作为内置角色保留，使用 `roles.system_key` 保护。Administrator 权限固定为全权限；内置角色不能改名或删除，Operator/Maintenance 的权限仍可由具备 `ManageRoles` 的管理员调整。默认管理员账号不能停用或改派角色。
5. 自定义角色必须至少保留一项有效权限；删除角色前必须确认没有关联用户。历史保留权限 `ManageRecipes` 不在当前矩阵展示，但替换权限时继续保留，避免无关数据丢失。
6. 用户管理支持新增、编辑显示名/角色/启用状态、解锁和重置其他用户密码。初始或重置密码只保存散列值，并强制下次登录改密；不在本页面提供物理删除账号。
7. 所有写操作由 `IdentityAdministrationService` 统一执行授权、输入校验、事务和审计；UI 校验只用于改善交互体验，不能作为安全边界。

## 数据与迁移

- SQLite schema 版本升级到 v5。
- `roles` 增加可空 `system_key` 字段，并为内置角色回填标识；建立非空值唯一索引。
- 为已有 Administrator 补写 `ManageRoles` 权限。
- 新建数据库仍创建三类内置角色和默认管理员，权限目录中的新代码自动进入 Administrator。

## 验证

- 核心权限服务测试覆盖依赖补全、历史权限保留、用户生命周期、管理员保护和越权审计。
- SQLite v3→v5 迁移测试覆盖记录迁移、旧表删除、角色标识和 `ManageRoles` 回填。
- App 测试覆盖角色权限保存、用户创建、角色变更持久化以及重新登录读取新角色。
