# ADR-0012：多设备、多协议点位管理的配置身份与校验边界

状态：已接受
日期：2026-09-05

## 背景

现有模板以单个仿真运行时为核心，设备配置和点位配置分别保存，点位只能通过协议和地址定位。该方式无法表达多个设备使用相同地址、共享串口资源或同一试验信号固定绑定到某台设备的场景。

## 决策

1. 配置关系固定为“通信通道 → 设备 → 点位”。通道拥有 TCP/串口/仿真资源；设备通过 `ChannelId` 和编译期注册的 `DriverKey` 选择传输与驱动；点位只保存 `DeviceId`，不再独立决定真实驱动。
2. 通道、设备和点位分别使用持久化 GUID 身份。名称和显示编码可以修改，不能因此改变绑定关系；设备编码项目内唯一，点位编码项目内唯一。
3. 点位地址在配置边界使用结构化字段，并由驱动描述生成规范地址。地址唯一性按 `DeviceId + 规范地址` 校验，不同设备允许相同协议地址，同一设备完全重复地址拒绝。
4. 设备、点位和仿真配置以 schema v2 表达；信号绑定单独使用 schema v1，并由完整快照统一校验。旧 v1 文件只能经过显式内存迁移生成候选，迁移不覆盖旧文件、不自动生效。
5. 驱动描述只负责能力、配置和地址校验，不执行硬件 I/O。未实现驱动可以出现在禁用草稿中，但启用时必须被拒绝；不提供自动回退仿真的路径。
6. 第一阶段保留全局 Simulation/Hardware 模式、现有写入安全边界以及 `ReadBackEqual` 写入策略；真实 Modbus/S7 驱动留到后续阶段按型号和平台单独验证。

## 影响

- 运行时后续必须按 `PointId → DeviceId → ChannelId` 路由，缓存不能再只使用地址。
- 配置应用必须以完整候选快照为单位，不能分别保存 device.json 和 points.json 后宣称已生效。
- 当前根目录 v1 示例继续作为迁移种子；在自动迁移和版本存储接入前，不改变现有示例的运行模式。
