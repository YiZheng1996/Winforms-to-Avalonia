# W06 仿真执行闭环实施记录

日期：2026-11-14。范围：当前 Template 工程；按本轮确认的基础补齐、操作保护和协调器工作开展。

## 1. 本轮实现

- 新增 `TestRunCoordinator`，调用现有 `TestRunPreparationService`、`TestRunStartPersistenceService` 和 `TestRunFinalizationService`，串通准备复核、原子开始、单项/自动后台执行、停止、终态与 Pending 报表原子保存。
- 同一准备绑定一个开始请求；成功开始后重复请求只返回原句柄。开始事务结果不明或无法证明本次新建时，不启动执行器。
- 共享 `DeviceOperationCoordinator` 增加跨后台任务的操作占用。准备、运行、收尾、待恢复期间，配置应用、手工诊断、手工写入和模式重新初始化/重连不能进入。手工写入不再能仅靠调用方传入 `ActiveRunOk` 绕过占用。
- 新增内部 `SimulationRunDeviceAccess`，只接受纯仿真、只读信号。固定准备时连接代次及配置，检查运行时身份、信号白名单、样本质量和新鲜度；连接变化后许可失效，不重新接纳新代次。接口始终拒绝写入，未创建真实设备许可。
- `SimulationPressureExecutor` 输出 `Pressure` 结构化测量，保留单位、来源、质量、配置与连接代次。协调器验证执行器输出合同；缺必需测量属于执行失败，不写产品“不合格”。
- 停止与终态冻结使用同一操作门仲裁，执行任务只创建一次。只读仿真收尾通过撤销许可完成，不把它当作真实台架安全动作。
- 开始前保存安装级操作标记；终态与 Pending 保存成功后才清除标记并释放占用。项点保存或终态提交不明时进入 `RecoveryRequired`。重新创建协调器后发现未闭合标记/Running 记录会拒绝准备，不自动续测。
- 冻结报表输入包含产品号、车号、参数、项点测量、模拟模式和资源摘要。自动报表请求/版本 ID 从 RunId 稳定派生；这里只创建 Pending 意图，没有计算或生成 Excel。
