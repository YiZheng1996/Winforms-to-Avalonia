# W07 报表计算与归档基础实现记录

日期：2026-11-16

状态：通用报表请求、计算和归档基础已编码；尚未接入 App 启动/完成流程、受控恢复或人工重试。

## 本次实现

- 新增 `ReportGenerationWorker`，按本机所有者串行处理自动 `Pending` 报表。领取后核验冻结输入、数据库实例、模板/映射摘要和用途，再调用计算引擎；只有产物归档并发布 manifest 后，才在同一数据库事务中完成报表和主记录判定。
- 产品判定计算结果必须显式声明 `ConclusionSource=ExcelFormula`，并将原始结论精确匹配到模板声明的合格/不合格值。
- 新增 `LibreOfficeReportCalculationEngine`，先将工作副本设为自动计算，再使用独立用户配置目录、独立输出目录和请求超时；检查模板映射声明的公式目标已重算且无错误，并从配置的总判定目标读取结论。总判定位置由各模板映射配置，不写死在通用 worker。
- 新增 `ReportTemplateMappingV1`，从冻结 JSON 映射绑定模板与映射 SHA-256；映射仅能引用现有白名单元数据、固定参数、项点测量和报表系统字段。
- 新增 `IModelResourceStore` / `FileModelResourceStore`，不可变资源通过键摘要引用并在读取时复核 SHA-256；新增 `FileReportCalculationRequestFactory`，只使用记录中的原始输入 JSON 与冻结资源版本，按强类型和单位填写独立 XLSX 工作副本，并拒绝覆盖公式目标。
- 请求同时绑定 RevisionId、AttemptToken 和隔离工作目录；worker 只归档本次工作目录内的输入/资源/计算结果，处理结束后清理已知尝试目录。
- worker 校验计算输出位于当前输入工作簿的隔离任务目录内，避免接收外部路径产物。
- 计算失败在同一事务中保存报表失败和主记录判定状态。取消或发布阶段结果不确定时保留 `Generating`，等待恢复流程查证，不自动重新计算。
- 新增 `FileReportStorage`，把文件流写入 StateRoot 下的暂存目录，核对长度和 SHA-256；发布不可变版本目录及 manifest。读取只接受 manifest 已列出的文件，导出通过同目录临时文件替换目标。
- 扩展失败仓储合同，失败报表与主记录判定状态在同一工作单元事务内更新。
