# W07 报表调度、发布恢复与失败重试

日期：2026-11-16

状态：通用 Pending 报表后台处理已接入组合根；已发布归档的提交恢复和有权限的失败重试已接入。报表模板尚未用项目真实资源验证；没有启用试验页面或真实设备。

## 本轮实现

- `ReportTaskDispatcher` 在安装级进程锁和已登记数据库生命周期内启动。启动先查证 `Generating` 任务，再周期读取持久队列，处理本节点 Pending 自动任务和授权人工重试任务。关闭时等待后台 worker 退出后才释放数据库和安装锁。
- 计算归档增加 `completion.json`，包含本次尝试令牌、数据库实例、计算引擎、原始结论、XLSX 摘要及 UTC 完成时刻。归档 reader 只读已发布 manifest，并校验其中所有文件摘要。
- `RecoverPublishedAsync` 只在任务仍处于 `Generating` 且任务令牌、数据库、终态记录、冻结输入、资源摘要和回执一致时，使用原 manifest 和原计算结果补交数据库关联。它不重新计算。计算尚未完成或没有发布回执时，任务保留 Generating，页面显示“生成中/待核查”；manifest/证据不一致则拒绝恢复并记录诊断。
- 失败重试从有效登录会话重新构造用户权限，并核验账号仍启用、未要求改密、未锁定及 `GenerateReports` 权限。仅允许本节点最新失败版本；成功版、其他活动版本、旧版本和非 Failed 任务不能重试。
- 重试使用原始输入及模板/映射摘要，生成新的 RevisionId/RevisionNo，并保留旧失败版本。新 Pending 和主记录判定复位在同一事务中；稳定请求标识使重复点击不会新建多个版本。重试动作写入审计。
- 报表页面显示版本、状态和失败原因；仅选中失败版本且有权限、后台工具配置齐全时开放重试。缺少工具/工作目录会说明当前仅支持查询。
- App 仅在安装级 `ReportToolPath`、`ReportWorkRoot` 以及存储配置齐全时注册真实 worker。没有注入仿真计算器或自动创建模板映射。现有旧试验入口仍停用。
