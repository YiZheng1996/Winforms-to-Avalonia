# 代码结构与修改入口

## 四个项目

- `src/XXX.TestBench.App`：页面、交互状态、启动装配。
- `src/XXX.TestBench.Core`：试验规则、应用流程、外部接口。
- `src/XXX.TestBench.Infrastructure`：配置文件、SQLite、日志、报表。
- `src/XXX.TestBench.Devices`：通信驱动、连接和仿真运行时。

Infrastructure 和 Devices 仅引用 Core；App 统一装配各项目。

## App 功能目录

`Features` 下按 Devices、Process、TestExecution、Products、Reports、Identity、Diagnostics、Shell 分组。各功能目录内的 Views 与 ViewModels 配套维护。公共对话框和页面基类位于 Shared。Composition 负责创建依赖及生命周期。

本轮保留原有命名空间和 XAML 类型名称，避免目录调整影响绑定和调用。新增文件优先放在对应功能目录，不再向原 Views/ViewModels 平铺。

设备配置编辑已按 ChannelEditorViewModel、DeviceEditorViewModel、DeviceConfigurationEditorViewModel 分文件；相关选项与行模型位于 DeviceConfigurationModels.cs。

## 通用能力与示例

设备安全写入、权限、审计、配置一致性检查属于通用能力。`Devices/Executors/SimulationPressureExecutor.cs` 与 App 的气动图形控件属于压力/气动场景示例；复制到新项目时应检查并替换其业务含义。仿真通过不代表真实设备验证。

## 构建与验证

默认外部构建目录为 `D:\Codex相关\XXX.TestBench.Template\artifacts`，可通过 MSBuild 的 `ArtifactsPath` 属性覆盖。脚本支持 `-TaskRoot`，用于隔离不同任务的缓存和结果。

```powershell
pwsh -File tools/build-and-test.ps1 -TaskRoot 'D:\Codex相关\my-template-validation'
```

## 后续职责收敛

设备点位工作区的状态与操作仍需逐项梳理；partial 文件不等于职责解耦。主界面和部分页面仍共享 ShellServices，应逐页改为明确的依赖参数，并沿用现有行为测试。外围历史目录暂保留原路径，避免破坏未确认的引用。
