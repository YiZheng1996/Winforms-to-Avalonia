# 信捷 PLC Modbus TCP 现场只读验证清单

## 目的与范围

本清单用于对“信捷 PLC（现场验证配置 V1）”进行现场只读核对。当前软件地址合同仅覆盖 D、HD、M、HM 四类地址和 Modbus TCP；本清单不扩大型号、地址区、数据类型或批读上限的支持范围。

现场核对期间不得执行 PLC 写入，不得把点位设为读写以验证写功能，不得更改 PLC 程序、寄存器值或现场通信参数。Socket/TCP 建连成功只表示传输可达；必须收到有效点位响应后才能记录协议读取成功。软件自动化用例和仿真结果不能替代现场验收。

## 开始前

- 记录 PLC 完整型号、固件版本、通信模块/接口、PLC 程序版本及现场负责人。
- 从设备/PLC 责任方取得允许读取的点位表、区域解释和数据类型依据；选择不会触发动作的已知值只读点。不得根据 D/HD/M/HM 编号自行推断厂家可用范围。
- 确认上位机地址、PLC 地址、TCP 端口、站号和网络路由由现场负责人核实。本软件新建设备建议值不是现场地址依据。
- 记录应用版本、目标配置 Revision、驱动键 modbus-tcp、型号键 XINJE_FIELD_V1 和执行时间。
- 备份当前完整设备配置。现场验证配置只在授权的测试设备/窗口中启用。
- 确认现场操作员知道本轮仅读取；本清单不包含写入验证步骤。

## 地址映射和类型核对

软件按以下规则生成标准 Modbus 偏移。逐个点位与现场点表/PLC 责任方给出的地址和类型核对；该换算规则本身不构成厂家范围证明。

| 原生地址 | Modbus 区域与偏移 | V1 类型 |
|---|---|---|
| D(n) | HR:n | UInt16、Float32、Int32、UInt32 |
| HD(n) | HR:(41088+n) | UInt16、Float32、Int32、UInt32 |
| M(n) | C:n | Bool |
| HM(n) | C:(49408+n) | Bool |

以下内容必须拒绝并记录，不得通过改成其他地址或类型来绕过校验：偏移超出 0～65535、寄存器位地址、未列出的区域前缀、M/HM 非 Bool、D/HD 非上述四种类型、同设备协议范围重叠、文本地址和已保存 Area/Offset 不一致。

## 现场只读步骤

1. 启动前检查应用显示的设备系列、设备端点、站号、字节序、字序和 Revision 与已审核记录一致。
2. 建立 TCP 连接后，先读取一项经确认的只读已知值。分别记录 TCP 传输状态、首个有效 Modbus 响应和点位质量；不能仅凭“连接成功”判为在线。
3. 对已知点逐项核对原生地址、规范 Modbus 区域/偏移、数据类型、质量和值。Float32、Int32、UInt32 必须使用现场已确认的类型语义；不要从寄存器内容猜类型。
4. 读取 M/HM 时核对响应为线圈 Bool。读取 D/HD 时核对响应为保持寄存器数值。只纳入只读点位，不执行写入或写后回读。
5. 检查批读请求记录：仅同一原生区的连续点可以合并；存在地址空隙时必须拆批，不应读取未配置空隙；D、HD、M、HM 不得互相合批。逐项记录起始偏移、请求数量及成功覆盖的点位。
6. 连续读取时记录每个点的质量、时间和值。将数值与 PLC 责任方指定的只读参考值或可信 HMI/仪表显示核对，并记录容差来源。应用运行时值与参考值不符时停止验收，先核对地址、类型、字序、站号及单位。
7. 如需验证网络中断或恢复，另行确认维护窗口和影响范围；不得为了测试而操作 PLC 输出或制造生产网络中断。未执行时标记“未验证”。
8. 结束后保存读取记录和配置 Revision。发现错误时停止读取、恢复已备份的应用配置并记录原因；不要手改 active.json 或 PLC 数据。

- 首次有效点位读取：通过 / 失败 / 未验证
- 连续批读、区边界及空隙拆批：通过 / 失败 / 未验证
- 已知值与字序核对：通过 / 失败 / 未验证
