## 4. 必须保持的功能合同

### 4.1 数据与业务

- 产品类型、型号、项点自增 ID 不变；型号所属类型不变；项点顺序不变。
- 当前项目级参数和产品类型＋型号组合参数语义不变。
- RecordNumber、产品标识、历史参数/序列/信号快照原文不重写。
- 历史已完成记录、结果和报表关联不删除；无快照的历史记录仍允许原有只读查询。
- 不恢复旧 test_tasks、配方发布、类型级参数页面。
- 不把 DataType 名称规范化扩大为物理数据类型转换。

### 4.2 设备与写入

- 每台设备独立 Simulation/Hardware；混合运行继续支持。
- 硬件初始化失败保持故障，不自动转仿真。
- 写入始终经 DeviceWritePipeline；权限、活动试验规则、联锁、高风险确认、新鲜回读、审计不弱化。
- 超时、取消、回读失败、审计失败后的不确定结果处理保持；不得自动重发。
- 配置切换、写入、试验执行和诊断仍共用现有协调机制。
- 降级期间固定禁止写入；删除 DiscardWritesWhileDemoted 不改变该规则。
- 工艺页面仍读缓存；诊断复用已有运行时；不因校验或转换创建硬件连接。
- “连接成功”“协议读成功”“指令已确认”“动作反馈到位”继续明确区分。

### 4.3 地址和导入

- Modbus 00001/10001/30001/40001 与 C/DI/HR/IR 的明确地址解析保留。
- 信捷 XINJE_FIELD_V1 的 D/HD/M/HM、固定设备排列、类型限制、地址占用检查保留。
- S7 地址解析、S7 解码选项、优化块访问确认保留。
- 点位 DEFAULT 分组、未分组展示、复制/粘贴/剪切/移动/导入合并继续可用。
- 模板仍为 v7、文件名“设备点位导入模板.xlsx”，工作表为“点位模板/填写说明/填写示例”。
- 九列顺序固定：点位标签、地址、数据类型、访问权限、原始下限、原始上限、工程下限、工程上限、说明。
- 不恢复旧列、英文表头别名、点位级 Modbus 字节序，不把 CSV 替代 XLSX。
- 现用中文类型显示、下拉顺序和设备型号约束保持；布尔的边界别名可接收，保存只写 Bool。

### 4.4 不属于废弃兼容的接口默认

ITestItemExecutor.RequiredSignals/OptionalSignals 的合法空集合可保留；不能强迫无设备依赖的计算执行器读取点位。

### 10.3 输出和幂等

1. 所有问题汇总完成，存在阻断项时不产生可生效输出。
2. 以规范候选 JSON 内容的 SHA-256 构成新 revision 标识，覆盖全部四文件有效内容；不能只用 ID 列表生成，避免同 ID 不同值产生碰撞。

### 14.4 v7 转换前置检查

check-db 应检查：

- user_version=7，当前全部必需表、列、索引及外键符合已知 v7 合同。
- app_metadata.schema_version 历史值可能仍为 1：当前代码没有随每次迁移同步它，不能仅因此拒绝合法 v7；按 user_version＋真实结构确认，并在报告标注修正。
- PRAGMA integrity_check 为 ok，foreign_key_check 无错误。
- 没有 Running 记录；工具不结束或删除活动记录。
- 三张待重建表上没有未知触发器/自定义列/依赖索引；有扩展则报告并阻断，禁止丢掉扩展。
- 其他表中的未预料依赖，尤其引用 code 的视图/触发器，必须显式列出，不能盲目 DROP。
- 权限 7 是本次已知废弃值；未知权限值报告阻断，不能统一 DELETE 不在 ActiveCodes 的所有行。
- 同型号多条记录、空历史快照属于可能合法存量，不要求补齐才升级。

### 14.5 WAL、一致性副本和源库保护

工具只升级输出副本，来源不建表、不改版本。

默认要求来源应用已关闭；如仍有 writer/未完成 WAL 状态，check 报告，convert 拒绝未经处理的文件复制。

支持以下一种经过验证的实现即可：

1. 使用当前 SQLite provider 的一致性备份接口，生成输出库，并在测试中覆盖 WAL 有未 checkpoint 数据的情况。
2. 在现场已正常停止应用且 WAL 完整合并后复制来源文件；复制前核实锁和 WAL 状态，禁止只凭进程名猜停机。

没有经过验证的一致性备份能力时选择第 2 条并明确前置要求，不写通用 File.Copy 即宣称兼容 WAL。check 不执行 checkpoint；若必须 checkpoint，应作为现场明确操作，不在只读检查内偷偷进行。

### 14.6 三张表重建事务

只在输出副本、同一独占连接上执行：

1. 保存三表原始 sqlite_sequence.seq，保存原始行数、ID 集合、保留字段行摘要。
2. 在事务外关闭该连接 foreign_keys；立刻验证确实关闭。生产池保持关闭/未创建，不从另一个连接执行迁移 SQL。
3. 开始事务。
4. 创建 product_types_v8、product_models_v8、test_item_points_v8，最终结构不含 code。
5. INSERT 显式列名复制全部保留字段，保留 ID。
6. 核对复制行数/ID/保留字段一致。
7. DROP 三张原表；将三张 _v8 表改回原名称。不要先把原父表 RENAME 为 old，避免 SQLite 自动把子表外键指向 old。
8. 恢复 sqlite_sequence 至 max(原 seq, 当前 MAX(id))，防止删除过最大记录后重用旧 ID。
9. 仅 DELETE role_permissions WHERE permission_code=7；其余角色权限逐条保持。
10. 保持已存在 Administrator 的有效权限；如果新当前权限目录要求全部权限，按明确目录补齐管理员，不提升其他角色权限。
11. 在事务内运行 foreign_key_check 和保留字段/关联核对；任何不一致回滚。
12. 最后更新 PRAGMA user_version=8 和 app_metadata.schema_version=8。
13. 提交。
14. finally 恢复该连接 foreign_keys=ON 并核实；失败输出标为不可用。
15. 关闭迁移连接，重新打开输出库，检查 integrity_check、foreign_key_check、版本和最终 schema。

表复制列合同：

~~~sql
-- 以下列合同用于生成并审阅实际 SQL；建表定义取 SqliteSchemaV8。
INSERT INTO product_types_v8 (id, name, is_enabled, created_at_utc)
SELECT id, name, is_enabled, created_at_utc FROM product_types;

INSERT INTO product_models_v8
    (id, product_type_id, name, is_enabled, created_at_utc)
SELECT id, product_type_id, name, is_enabled, created_at_utc
FROM product_models;

INSERT INTO test_item_points_v8
    (id, product_type_id, name, executor_code, result_kind, is_enabled,
     sort_order, created_at_utc, updated_at_utc)
SELECT id, product_type_id, name, executor_code, result_kind, is_enabled,
       sort_order, created_at_utc, updated_at_utc
FROM test_item_points;
~~~

无损范围是所有保留业务字段和关联；删除 code 与权限 7 是明确设计变更，旧值仍在原始备份中。整个数据库物理字节哈希因页布局变化不要求相等，业务逐表规范摘要必须相等或仅含这两类明确差异。

### 19.2 PowerShell 环境和构建

~~~powershell
$projectRoot = 'D:\易峥\2026\2026-09\Avalonia_上位机通用模板\项目代码\XXX.TestBench.Template'
$taskRoot = 'D:\Codex相关\compatibility-cleanup-20260928'
$artifactRoot = Join-Path $taskRoot 'artifacts'
$resultRoot = Join-Path $taskRoot 'test-results'
$tempRoot = Join-Path $taskRoot 'temp'
$envNames = @(
    'TEMP', 'TMP', 'NUGET_PACKAGES', 'NUGET_HTTP_CACHE_PATH',
    'NUGET_PLUGINS_CACHE_PATH', 'DOTNET_CLI_HOME'
)
$savedEnvironment = @{}
foreach ($name in $envNames) {
    $savedEnvironment[$name] = [Environment]::GetEnvironmentVariable($name, 'Process')
}

New-Item -ItemType Directory -Force -Path $taskRoot, $artifactRoot, $resultRoot, $tempRoot | Out-Null

try {
    $env:TEMP = $tempRoot
    $env:TMP = $tempRoot
    $env:NUGET_PACKAGES = Join-Path $taskRoot 'nuget-packages'
    $env:NUGET_HTTP_CACHE_PATH = Join-Path $taskRoot 'nuget-http'
    $env:NUGET_PLUGINS_CACHE_PATH = Join-Path $taskRoot 'nuget-plugins'
    $env:DOTNET_CLI_HOME = Join-Path $taskRoot 'dotnet-home'

    Push-Location $projectRoot
    try {
        dotnet restore '.\XXX.TestBench.Template.sln' '-p:UseArtifactsOutput=true' "-p:ArtifactsPath=$artifactRoot"
        if ($LASTEXITCODE -ne 0) { throw '还原失败，不能继续宣称构建通过' }

        dotnet build '.\XXX.TestBench.Template.sln' -c Release --no-restore --artifacts-path $artifactRoot --nologo
        if ($LASTEXITCODE -ne 0) { throw '构建失败' }

        $projects = @(
            'XXX.TestBench.Core.Tests',
            'XXX.TestBench.Integration.Tests',
            'XXX.TestBench.App.Tests'
        )
        foreach ($testName in $projects) {
            $testProject = Join-Path $projectRoot "tests\$testName\$testName.csproj"
            $testResult = Join-Path $resultRoot $testName
            dotnet test $testProject -c Release --no-build --artifacts-path $artifactRoot --results-directory $testResult --logger 'trx;LogFileName=results.trx' --nologo
            if ($LASTEXITCODE -ne 0) { throw "$testName 验证失败" }
        }

        $headlessProject = Join-Path $projectRoot 'tests\XXX.TestBench.App.Headless.Tests\XXX.TestBench.App.Headless.Tests.csproj'
        dotnet test $headlessProject -c Release --no-build --artifacts-path $artifactRoot --results-directory (Join-Path $resultRoot 'Headless') --logger 'trx;LogFileName=headless.trx' --blame-hang --blame-hang-timeout 120s --blame-hang-dump-type none --nologo
        if ($LASTEXITCODE -ne 0) { throw 'Headless 失败或超时；不得按日志文字判成功' }
    }
    finally {
        Pop-Location
    }
}
finally {
    foreach ($name in $envNames) {
        [Environment]::SetEnvironmentVariable($name, $savedEnvironment[$name], 'Process')
    }
}
~~~

执行者仍需读取 TRX，确认总数、失败数、跳过数，不以退出码 0 掩盖“没有发现任何测试”。

--blame-hang-timeout 主要约束测试执行，不等于整个进程绝不会挂住。若测试结束后进程不退出，监督器使用本次启动 PID 及其子进程范围超时终止，并记为超时未通过；不扫描杀掉系统内所有 testhost。

如需要后台 Start-Process，使用 -WindowStyle Hidden，日志定向到本任务目录；参数中包含空格路径要按 PowerShell 参数数组正确引用。不要把以上示例改成跨 shell 拼接删除命令。

### 20.1 开发阶段

1. 使用独立夹具生成 v7 数据库和支持的旧配置；工具生成新输出。
2. 核对 T001～T104 所涉及的行为，不接触真实部署目录。
3. 发生代码问题仅撤销本次具体 diff/hunk；对原有未提交内容有疑问时停止该文件回滚。
4. 不使用 git reset --hard、git clean、整体 checkout 恢复工作区。
5. 数据库迁移失败只将独立输出标为失败，原数据保持；不触发代码“恢复默认配置”。

### 20.2 现场部署前必须已有的材料

- 目标 EXE 的真实绝对路径及实际 config/data 根目录；不能以源码 config 代替。
- 数据库及配置版本清单，是否存在 Running 记录、未知字段、设备端点冲突。
- 升级工具 check 报告，所有阻断项已处理。
- 完整旧应用、配置、数据库、关联报表/模板及恢复说明的持久备份。
- 一份来自该部署副本的转换与恢复演练记录。
- 现场授权及停机窗口；本方案编制不替代它。

### 20.3 部署推荐顺序

1. 停止试验及设备动作；确认没有活动试验，正常退出应用。
2. 确认数据库连接均已关闭，WAL 状态满足一致性备份要求。
3. 备份整个实际配置集和一致性数据库；记录文件哈希、数据库逻辑摘要和旧程序版本。
4. 对备份副本执行 check，再分别生成新配置和 v8 数据库输出；来源不改。
5. 在独立验证环境确认输出能够被新程序读取；验证环境禁止真实硬件连接，使用专门 Simulation/假客户端夹具，不能直接启动带真实 Hardware 端点的现场副本。
6. 发布新程序到新的部署目录，配套放入已审阅的当前配置和 v8 数据库；保留现场原 DeviceMode，不为启动测试偷偷改为仿真后忘记恢复。
7. 在现场授权下首次启动，确认实际加载版本、记录可查、权限正常、配置未被覆盖。
8. 如需真实设备读写验收，另按现场清单实施，未完成前不称为设备功能验收通过。

数据库和配置输出不是一个跨文件系统原子事务。采用“完整新目录准备好后切换入口”的部署方法避免程序一半新、一半旧；切换路径如何生效由现场启动方式决定，不能擅自修改服务或快捷方式。

### 20.4 回滚决策

| 情况 | 处理 |
|---|---|
| 新程序还未产生任何新业务数据 | 停止新程序，恢复整套旧应用＋旧配置＋旧数据库 |
| 新程序已经产生试验记录/审计/报告 | 先保存新数据，停止写入；制定数据合并/回收方案，不直接覆盖回旧库丢数据 |
| 只有源码编译失败 | 撤销本次局部改动，不改数据 |
| 新配置应用失败但回滚成功 | 保持旧当前版本，显示失败原因 |
| 回滚运行时或指针失败 | Faulted，停止危险操作，人工按已验证备份恢复 |
| 旧程序试图打开 v8/新配置 | 应拒绝或由部署阻止；不能靠把版本号改回旧值“降级” |

禁止只还原主 db 而遗漏 WAL/关联配置，也禁止只恢复旧 active 指针但保留不匹配的新程序/数据库。

### 20.5 阻断项与可继续工作

以下只阻断对应数据升级/部署，不阻断独立源代码实现：

- 未知旧数据库版本或实际数据关系。
- 端点冲突、双类型/双量程冲突。
- Running 记录或来源仍被使用。
- 自定义列/触发器/权限值超出本方案。
- 未能获得一致性数据库副本。

必须报告对象、文件/记录 ID、原因及需要的最少信息；不要用默认值、模糊匹配、删行、改状态解决。

## 21. 风险登记与防误改规则

| 风险 | 常见误改 | 必须保护 |
|---|---|---|
| 启动失效 | 先删迁移，默认 device 仍 v3 | W02/W03/W04 配套交付 |
| 点位串设备 | 以 Code/地址代替 GUID | 已保存对象身份强校验 |
| PLC 目标改变 | 删除端点来源前未确认冲突 | 转换报告明确全部来源 |
| 类型失真 | Boolean 清理连带 Decimal→Float32 | 仅 Bool 同义归一 |
| 写入误判 | 原始值为空时使用工程值 | 原始回读及会话身份核对 |
| 数据丢失 | 运行旧 v4 DROP 项点结果脚本 | 不支持的旧库明确拒绝 |
| 自增 ID 重用 | 只保留 MAX(id) | 保存 sqlite_sequence 高水位 |
| 权限漂移 | 删除枚举后自动连续编号 | 显式数值保留，7 留空 |
| 测试误绿 | 超时日志有“通过”就成功 | 退出码＋TRX＋未超时 |
| 他人进程被杀 | 按名称杀所有 testhost | 本次 PID/进程树限定 |
| 误删现用页面 | Recipe 文件或 PointRow 看起来旧 | 按真实调用和绑定迁移 |
| 现场数据被覆盖 | 发布包覆盖 active/data | 独立目录、转换副本、明确部署 |
| 兼容搬家不收敛 | App 仍引用 Upgrade/旧 DTO | 生产依赖图检查和发布检查 |
| 过度改造 | 改 ORM、UI、协议或通用平台 | 按白名单和逐项验收控制范围 |
