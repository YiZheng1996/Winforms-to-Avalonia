## 3. 固定设计决定

### 3.1 标识与归属

- ChannelId、DeviceId、PointId 均为创建时生成、持久化的 GUID 字符串；改名称不改 ID。
- DeviceCode、PointCode 为项目内不区分大小写的唯一编码；保留旧点位 Code 作为 PointCode，兼容展示及检索。
- Name 允许修改；点位名称允许不同设备重复。
- 点位只保存 DeviceId，不再独立决定驱动。设备保存 ChannelId 和 DriverKey。
- DriverKey 使用注册表固定值，例如 `simulation`、`modbus-rtu`、`modbus-tcp`、`siemens-s7`。PLC 型号使用独立 Model/Profile 字段。
- 未实现驱动可在草稿中显示为不支持，但禁止作为启用的 Hardware 设备应用。
- 不提供未知驱动自动降级路径。

### 3.2 通道、设备和点位字段

| 对象 | 字段及默认策略 |
|---|---|
| ChannelEntry | Id、Name、TransportKind、Enabled、TimeoutMs、RetryCount、连接参数；TimeoutMs 迁移旧值，RetryCount 默认 0 |
| TCP 参数 | Host、Port；端口范围 1–65535，Host 必填 |
| Serial 参数 | PortName、BaudRate、DataBits、Parity、StopBits；同一串口禁止多个启用通道重复占用 |
| Simulation 参数 | 仿真通道标识；不打开 TCP 或串口 |
| DeviceEntry | Id、Code、Name、ChannelId、DriverKey、Manufacturer、Model、Enabled、PollIntervalMs、StaleAfterMs、驱动专用参数 |
| Modbus 设备参数 | UnitId；站号范围及广播限制由传输/驱动验证，第一版不支持广播写 |
| S7 设备参数 | CpuProfile 以及该驱动实际需要的 Rack/Slot 或 TSAP；互斥选项由 Profile 约束，不强行所有字段必填 |
| PointEntry | Id、Code、Name、DeviceId、Enabled、地址定义、RawDataType、DecodeOptions、Scale、Unit、IsWritable、RiskLevel、WritePolicy、Description |
| WritePolicy | 第一版只支持读写寄存器的 ReadBackEqual；数值容差明确配置，默认保持现有行为；命令脉冲/只写点见 6.3 |

连接参数采用强类型可选对象加判别字段：Tcp / Serial / Simulation 必须恰好选中一个。JSON 未知字段或矛盾参数必须提供可定位错误；禁止用任意字符串字典贯穿领域层。

默认 PollIntervalMs 迁移旧全局值；新设备默认 500 ms。StaleAfterMs 默认 max(3 × PollIntervalMs, 2 × TimeoutMs)，允许修改但必须大于 0。默认值不代表所有现场设备都适用。

### 3.3 地址与类型

- Modbus：Area（Coil/DiscreteInput/InputRegister/HoldingRegister）、Offset（统一零基协议偏移）、可选 BitIndex。界面允许辅助录入手册地址，但必须明确起算规则并显示转换结果，禁止直接把 40001 当协议偏移。
- S7：Area、DbNumber（适用时）、ByteOffset、BitOffset（位点适用）；具体区域及范围由 CpuProfile/驱动验证。
- 仿真：使用独立逻辑地址，不参与真实协议解析。
- RawDataType 第一批支持 Bool、Int16、UInt16、Int32、UInt32、Float32；明确位、字节、寄存器数量。旧 Decimal 仿真点保留模拟 Decimal 类型，不猜测真实 PLC 类型。
- DecodeOptions 明确字节序和字序；驱动先解码原始值，再进行工程换算。严禁重复换算。
- 线性换算沿用原始上下限/工程上下限；原始上下限相等时拒绝。可写点要求换算可逆，执行逆换算后检查溢出和整数舍入策略（首版非整数拒绝）。
- 非有限浮点值、解码失败标记 Bad，不转成 0。
- 地址唯一键为 DeviceId + 驱动生成的规范化地址；不同设备同地址合法。第一版同设备完全重复地址拒绝，不支持别名。
- 不同长度/位地址重叠需做范围分析：只读重叠提示；涉及可写重叠第一版拒绝，避免读改写冲突。越界地址直接拒绝。

### 3.4 文件版本和配置集合

- DeviceConfig、PointsConfig 结构版本升为 2；SimulationConfig 因改 PointId 关联也提升版本，实际旧版本号先核对。
- 新增 DeviceConfigurationSnapshot，包含 Revision、DeviceConfig、PointsConfig、SimulationConfig、SignalBindingsConfig。
- 新增信号绑定文件 `signal-bindings.json`，初始 schemaVersion 为 1；第一阶段可为空，但作为配置集合成员共同校验和应用。
- `app.json` 保持原职责，不纳入本轮设备配置编辑。
- 根目录现有配置作为首次启动种子/旧版本迁移来源；一旦存在生效清单，禁止绕过清单直接加载根目录旧文件。

## 5. 采集、状态与故障规则

### 5.1 调度

- 每个启用通道最多一个串行请求执行器；首版 TCP 通道也串行执行，后续有性能证据再做并发。
- 不同通道独立任务，不允许一个设备超时阻塞所有设备。
- 同通道设备按轮询到期时间公平调度；限制队列长度，同一设备重复轮询合并，不积累无限请求。
- 读写共用通道互斥；写请求可以优先但不能永久饿死读取。
- 驱动按连续地址、数据区域和协议上限组批；先验证正确性，再优化批量。不能跨设备合并。
- 取消、停止、应用配置时清空待执行写请求；旧请求不迁移到新连接或新版本。
- 通道句柄故障才重建共享通道；某从站超时只更新该设备状态，不能无条件关闭其他从站正在使用的总线。

### 5.2 数据及状态

PointValue 增加 PointId、DeviceId、Revision、ConnectionGeneration；保留 PointCode、Address 仅作诊断兼容。TimestampUtc 表示实际采集完成时间，不是 UI 刷新时间。

- 缓存主键统一使用 PointId；仿真、趋势及故障注入不得单用 Address。
- 连接重建增加代次；新配置增加 Revision。旧代次/旧版本迟到结果全部丢弃。
- 无初值为 Unknown；读取错误为 Bad；超过 StaleAfterMs 为 Stale（扩展 PointQuality 并更新所有分支）。
- 断线后可显示最后值，同时显示无效质量及最后成功时间；业务计算拒绝 Bad/Unknown/Stale。
- 设备状态至少区分 Disabled、Connecting、Online、Degraded、Offline/Faulted；与现有 DeviceHealth 建立明确映射。
- 聚合状态：所有启用设备有效在线才 Healthy；部分在线为 Degraded；全部不可用为 Faulted；连接初期 Unknown。禁用设备不计入健康分母。
- 零启用设备可保存草稿，但禁止应用为可运行配置。
- 总体 Degraded 不能直接决定某个写入是否可用；必须检查目标设备。

### 5.3 生命周期

Start/Stop/Dispose 必须幂等；启动部分失败时保留其他独立设备并汇报失败列表。停止先禁止新请求，再取消/等待后台任务，最后释放通道，所有等待有界。驱动不响应取消时，关闭其通道解除阻塞并记录超时；不得永久挂住退出。

## 6. 写入与试验依赖

### 6.1 写入管线

按当前生效版本重新定位点位 → 现有权限检查 → 模式一致 → 点位/设备/通道启用且目标设备可用 → 写入属性及输入类型/范围 → 活动运行状态 → 现有联锁 → 风险确认 → 逆换算 → 通道写入 → 新鲜回读 → 审计。

- 保留当前 ManualControl / CalibrateDevices 和高风险确认要求，不放宽已有边界。
- 不用其他设备在线证明目标设备在线。
- 配置应用与在途写入互斥；取消后禁止继续发出请求。
- 写入超时分为确定未发送、确定失败、结果不确定；已可能发送的命令不得自动重试。
- 审计包含用户、DeviceId、PointId、Revision、目标工程值、原始值、结果及回读值；失败/结果不确定也必须记录。
- 审计落库失败不能把已发出的写入描述为未发生，必须暴露审计错误且禁止自动重发。

### 6.2 业务信号绑定

第一版增加项目级 SignalBindingsConfig：SignalKey → PointId。绑定键由执行器声明，不能让用户随意生成执行逻辑。

- ITestItemExecutor 的元数据增加 RequiredSignals：信号键、用途（读/写）、预期类型、单位、最大允许样本年龄。
- 对 SimulationPressureExecutor 先查清真实读取逻辑，再声明其实际需要的信号；不虚构压力点名称。
- 新增 SignalResolver，从执行上下文的固定配置快照解析点位。启动预检与配置应用共用 DeviceOperationCoordinator。
- 首版一个 SignalKey 在项目中只有一个绑定，不提供按型号覆盖；如实际出现不同型号必须使用不同设备的需求，再另行扩展作用域。
- 开始试验前校验所有 RequiredSignals 已绑定、类型和单位匹配、设备可用、样本新鲜；无关设备故障不阻止启动。
- 执行期间必须逐次验证所需数据；依赖丢失终止相关执行并记录原因，不使用旧值继续判定合格。
- 可选信号首版只用于显示，不参与合格判定；不能把缺失的必需信号配置成“可选”绕过预检。
- 运行记录现有快照需包含 Revision 和已解析的信号映射。先复用已有快照存储；若容量/结构不适配，单独列明数据库迁移再实施，不偷改 ModelPointConfig 语义。
- 通信失效的安全停止动作由具体执行器定义；连接已断时不能承诺 PLC 停止成功，记录动作请求与确认状态。

### 6.3 第一版不开放的写入能力

只写点、脉冲命令、启动动作反馈、跨设备原子写不属于 ReadBackEqual。第一版拒绝配置为可执行写入；不能通过关闭回读来绕过。

若现场需要启动/复位命令，新增独立阶段，明确命令保持时间、幂等性、反馈点、超时、结果不确定和人工恢复策略后才开放。软件不承诺多台 PLC 的原子事务或同步采样。

```text
  device-config/

    revisions/<revision>/
      device.json
      points.json
      simulation.json
      signal-bindings.json
      manifest.json
```

revision 目录是有意保留的正式配置及恢复材料，不是临时文件。序列化工作文件、导入文件和验证中间文件统一放 `D:\Codex相关\多设备点位改造\`。创建 revision 后不原地修改；清单使用同卷临时文件和原子替换时，该文件属于正式存储事务机制，须限定在配置存储内部并在完成后清理，不作为通用缓存。

active.json 使用同卷原子替换保证只指向完整配置。首次创建与已有清单替换分别实现；保留上一生效清单。原子性、刷盘与异常恢复在目标平台测试，不能把两次独立 JSON 保存称为事务。

### 7.2 应用顺序

1. 在内存构造完整候选，完成权限、字段、引用、驱动能力及仿真绑定校验；编辑不改变生效对象。
2. 获取操作门，再次检查无活动试验，并暂停新写入与新试验启动。
3. 持久化新 revision 全部文件及哈希；失败不影响当前运行时。
4. 停止旧会话并确保所有通道释放；禁止新旧会话同时控制硬件。
5. 用新快照构造会话，检查资源能否建立及启动任务。单设备离线允许按 Degraded/Faulted 激活；显示离线原因，试验由依赖预检阻止。非法配置、端口占用、会话构造失败属于应用失败。
6. 原子切换 active.json；持久化失败则停止新会话并恢复旧快照会话，保持旧生效清单。
7. 在同一操作门内交换稳定门面的活动会话，公布 ActiveRevision，写审计，恢复操作入口。
8. 任何恢复失败进入明确 Faulted，禁止写入，展示旧/候选版本和错误，不继续显示“应用成功”。

崩溃恢复：重启只读取 active.json 所指且哈希完整的版本；清单损坏时使用可验证的上一生效清单并明确记录恢复事件。两者均无效进入配置故障页，禁止默默读取旧根目录种子。未被指向的候选 revision 不能自动生效。

UI 固定显示“当前生效版本”和“编辑未应用”。首版不单独提供“保存即生效”，也不把设备在线作为保存结果。

### 7.3 旧配置迁移

- 首次迁移仅在没有 active.json 时进行；先备份原文件，生成候选及迁移报告，不覆盖旧种子。
- 单一、归属明确的旧设备自动分配 DeviceId；多个候选设备须用户在迁移界面分配，不默认使用第一台。
- 原 PointCode 保留，生成 PointId；旧 Protocol 转为设备驱动，不兼容项阻止应用。
- 旧仿真初值、规则和故障注入按旧地址查找唯一点位后转换 PointId；找不到或匹配多个都列为错误，禁止静默丢弃。
- 迁移与新增配置使用同一完整校验器和应用流程；迁移重复执行不得生成另一批已生效 ID。
- 迁移失败可查看报告和修正映射；无有效配置时显示配置恢复页，不启动硬件。
