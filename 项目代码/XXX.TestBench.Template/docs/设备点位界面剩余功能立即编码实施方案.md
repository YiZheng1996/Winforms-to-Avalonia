## 1. 一页结论

设备点位页面不需要推倒重写。当前主线已经具备以下可复用基础：

- 通信通道 → 设备 → 点位分组的树结构；
- 点位新增、编辑、删除和分组调整；
- 通道、设备、分组编辑；
- 固定中文 Excel/CSV 导入、预览和应用；
- 模板下载；
- 业务信号绑定；
- 完整 JSON Revision、`manifest.json` 校验和 `active.json` 原子切换；
- 配置应用期间的活动试验锁、运行时替换和失败恢复；
- `IDeviceRuntime.ReadFreshAsync`、点位质量、采样时间、配置版本和连接代次模型。

本轮应采用“保留现有配置安全链，补齐页面功能闭环”的方式实施，分为五个编码阶段：

1. 固定行为合同并补齐统一操作反馈；
2. 接通点位复制、剪切、粘贴、移动和键盘操作；
3. 统一导入计划并增加“导出当前范围”；
4. 增加只读点位诊断，复用当前运行时连接；
5. 完成自动化、Headless 和人工验收。

真实 Modbus TCP、Modbus RTU、Siemens S7 硬件驱动不与上述页面功能混在同一批次。当前 `DeviceSession` 在 Hardware 模式仍会明确拒绝未实现驱动，只有取得真实设备型号、固件、通信参数、地址手册和现场测试条件后才能进入硬件驱动阶段。

## 2. 强制实施边界

### 2.1 主界面冻结规则

`DevicePointManagementView.axaml` 当前三栏结构、尺寸、颜色、字体、间距和控件位置视为已经确认，本轮不再做视觉改版。

允许的界面改动只有：

- 给现有按钮补充 `IsEnabled`、快捷键和自动化名称；
- 调整动态右键菜单的可用项；
- 使用现有 `NoticeDialogWindow` 展示操作成功或失败；
- 新增独立的“点位诊断”弹窗；
- 修复功能所必需的绑定，不改变页面视觉层级。

禁止：

- 重新排列主页面三栏；
- 修改现有样式体系；
- 把点位实时值硬塞入当前配置清单列；
- 为实现功能复制一套新的页面；
- 将 KEPServerEX 的品牌外观复制到本项目。

### 2.2 数据与安全边界

- 配置数据继续存放在完整 JSON Revision 中，不进入 SQLite。
- SQLite 只保存现有业务数据和审计数据，不为本轮新增设备点位表。
- 所有持久化变更必须经过 `DeviceConfigurationService`。
- UI、ViewModel、导入器不得直接写 `device.json`、`points.json` 或 `active.json`。
- 配置保存不等于向 PLC、仪表或从站写值。
- 本轮诊断只读，不新增设备写入入口。
- 任何配置应用失败都不能污染当前 Active Revision 或当前运行时。
- 活动试验期间必须在服务层拒绝配置应用；不能只依赖按钮禁用。
- 不允许静默级联删除通道、设备或被信号绑定引用的点位。

### 2.3 工作区保护

当前工作树已有大量设备点位相关未提交修改。编码时必须：

### 3.2 当前明确缺口

#### 缺口 A：操作结果不可见

`DevicePointManagementViewModel` 中大量方法只设置 `StatusMessage`，但当前 `DevicePointManagementView.axaml` 没有展示 `StatusMessage`。结果是部分保存、导入、删除失败只能在 ViewModel 内部看到，客户界面没有明确反馈。

处理原则：

- `StatusMessage` 继续保留，供测试和页面状态使用；
- 所有显式写操作同时返回 `OperationFeedback`；
- View 使用现有 `NoticeDialogWindow` 显示结果；
- 文件选择器取消、弹窗取消不显示失败；
- 刷新成功不弹窗，刷新失败必须显示。

#### 缺口 B：复制、剪切未实现，移动入口未接通

当前点位详情右键菜单中的“剪切”和“复制”被固定为不可用；`GetPointRowActions` 虽然返回 `MovePoint`，但当前点位菜单没有消费该动作，现有移动实现实际上没有稳定入口。

处理原则：

- 剪贴板只保存在当前进程内存中，不写配置文件，不写 `Para.ini`，不使用系统剪贴板；
- 复制粘贴创建新 `PointId`；
- 剪切粘贴在应用成功前不删除原点位；
- 剪切只允许同一设备内移动；
- 跨设备使用复制，并重新校验驱动、地址、数据类型和分组；
- 粘贴前必须打开点位编辑器确认，不能静默生成名称和地址。

#### 缺口 C：“导入/导出”只有模板下载，没有当前点位导出

当前菜单只有“导入点位”和“下载模板”。客户点击“导入/导出”时应能导出当前树范围中的实际点位，用于批量维护后重新导入。

处理原则：

- “下载模板”继续生成空白填写模板；
- “导出当前范围”写入当前范围的真实点位行；
- 当前范围跟随左树：根、通道、设备或分组；
- 导出使用 `DevicePointTemplateDefinition.Columns`，禁止复制表头定义；
- Excel 导出不是完整配置备份，不替代 Revision 和 `manifest.json`；
- 当前 v5 模板不暴露内部 `PointId`、`DeviceId`、`GroupId` 和风险等级。

#### 缺口 D：导入可能覆盖模板之外的安全字段

当前 v5 模板只有以下 9 列：

1. 点位标签；
2. 地址；
3. 数据类型；
4. 访问权限；
5. 原始下限；
6. 原始上限；
7. 工程下限；
8. 工程上限；
9. 说明。

模板没有风险等级、写入策略、字节序、字序和稳定身份。导入更新已有点位时，如果直接使用导入对象整体替换已有对象，就可能把已有高风险属性或其他高级字段覆盖成默认值。

强制规则：

- 对已匹配点位，保留现有 `Id`；
- 对已匹配且仍为可写的点位，保留现有 `RiskLevel`；
- 导入把已有点位改为只读时，`RiskLevel` 归一化为 `Normal`；
- 新增可写点位默认 `Normal`，导入不能直接把新点位提升为高风险；
- 保留模板未承载的 `WritePolicy`、`DecodeOptions` 及其他高级字段；
- 导入只修改模板明确承载的字段；
- 预览和最终应用必须使用同一份合并计划，禁止各自实现一套匹配规则。

#### 缺口 E：页面未使用现有运行时诊断能力

`IDeviceRuntime` 已提供：

- `GetDeviceStatus`；
- `ListDeviceStatuses`；
- `GetPoint`；
- `ReadFreshAsync`；
- `ActiveRevision`；
- `ConnectionGeneration`；
- `PointValue.Quality`；
- `PointValue.TimestampUtc`。

当前设备点位页只显示配置摘要，没有提供点位新鲜读取、质量和时间戳诊断。

处理原则：新增独立诊断弹窗，复用当前运行时和当前通道会话，不在主配置表中增加实时列。

## 4. 目标架构

### 4.1 配置变更主链

```text
界面输入或文件导入
        ↓
ViewModel 生成候选副本
        ↓
统一导入/编辑规则生成变更计划
        ↓
DeviceConfigurationService 校验权限、引用、驱动、地址、量程和活动试验
        ↓
DeviceConfigurationStore.StageAsync
        ↓
校验 revision 文件、manifest 和哈希
        ↓
创建并启动候选运行时
        ↓
CommitActiveAsync 原子切换 active.json
        ↓
发布候选运行时、释放旧运行时
        ↓
页面按 PointId/NodeKey 恢复选择和展开状态
        ↓
显示 OperationFeedback
```

### 4.2 失败原则

| 失败位置 | 必须结果 |
|---|---|
| UI 输入校验失败 | 不生成候选、不写文件 |
| 导入解析失败 | 不打开可应用预览、不修改当前目录 |
| 导入计划冲突 | 预览显示冲突，确认按钮不可用 |
| 配置校验失败 | 不 Stage、不切换 Active |
| Revision 写入或哈希失败 | Active 保持原版本 |
| 候选运行时启动失败 | Active 保持原版本，旧运行时恢复或保留明确故障 |
| Active 切换失败 | 候选运行时释放，旧运行时恢复 |
| 页面刷新失败 | 已生效配置不回滚，但明确提示页面刷新失败 |
| 用户重复点击 | 第二次请求直接拒绝，不进入配置服务 |

### 4.3 代码分层

| 层 | 职责 | 禁止事项 |
|---|---|---|
| View | 文件选择、弹窗、快捷键、右键菜单、显示反馈 | 业务校验、直接改配置对象、直接写文件 |
| App/ViewModel | 页面状态、动作可用性、候选编排、UI 状态恢复 | 直接操作 Excel、直接操作协议库 |
| Core/Application | 导入合并规则、配置应用、安全与权限 | 依赖 Avalonia、ClosedXML |
| Core/Ports | 导入、导出、配置存储、运行时边界 | 具体文件或 UI 实现 |
| Infrastructure | Excel/CSV、Revision 文件存储 | 决定权限和业务安全规则 |
| Devices | 当前运行时、通道调度、协议驱动 | 依赖页面或数据库 |

## 6. 新增核心合同

### 6.1 统一操作反馈

继续使用现有：

```csharp
public sealed record OperationFeedback(bool Succeeded, string Message);
```

设备点位页所有显式变更方法改为返回 `Task<OperationFeedback>`：

```csharp
Task<OperationFeedback> CreateFromDialogAsync(
    DevicePointDialogResult result,
    CancellationToken ct = default);

Task<OperationFeedback> UpdateFromDialogAsync(
    DevicePointRow row,
    DevicePointDialogResult result,
    CancellationToken ct = default);

Task<OperationFeedback> ApplyImportedPointsAsync(
    DevicePointImportPlan plan,
    CancellationToken ct = default);

Task<OperationFeedback> ApplyPointGroupAsync(
    PointGroupDialogResult result,
    CancellationToken ct = default);

Task<OperationFeedback> DeleteSelectedTreeNodeAsync(
    CancellationToken ct = default);

Task<OperationFeedback> MoveSelectedPointToGroupAsync(
    DevicePointGroupChoice targetGroup,
    CancellationToken ct = default);

Task<OperationFeedback> DeletePointAsync(
    CancellationToken ct = default);
```

约束：

- 方法同时设置 `StatusMessage`，但调用方不得只依赖它；
- 成功消息必须说明“已应用”；
- 失败消息保留具体校验原因；
- `OperationCanceledException` 显示“操作已取消”，不显示堆栈；
- 未知异常写应用日志，界面只显示安全可读消息。

### 6.2 页面单操作门

在新的 partial 文件中增加：

```csharp
private readonly SemaphoreSlim _pageOperationGate = new(1, 1);

private async Task<OperationFeedback> RunMutationAsync(
    Func<CancellationToken, Task<string>> action,
    CancellationToken ct);
```

规则：

1. 使用 `WaitAsync(0, ct)`，不能排队执行第二个客户写操作；
2. 未取得门时返回“已有设备配置操作正在执行，请稍候”；
3. 取得门后设置 `IsBusy = true`；
4. `finally` 中恢复 `IsBusy`、释放门并刷新全部 `Can...`；
5. `SaveEntriesCoreAsync` 等内部方法不再获取页面门，避免嵌套死锁；
6. Core 的 `DeviceOperationCoordinator` 继续作为最终跨页面互斥门，页面门不能替代它。

### 6.3 内存剪贴板

新增到 App 层：

```csharp
internal enum DevicePointClipboardMode

internal sealed record DevicePointClipboardPayload(
```

ViewModel 新增：

```csharp
private DevicePointClipboardPayload? _pointClipboard;

public bool CanCopySelectedPoint { get; }
public bool CanCutSelectedPoint { get; }
public bool CanPastePoint { get; }

public OperationFeedback CopySelectedPoint();
public OperationFeedback CutSelectedPoint();

    DevicePointDialogResult result,

```

`DevicePointPasteDraft` 至少包含：

- 模式；
- 源点位身份；
- 目标设备；
- 目标分组；
- 用于点位编辑弹窗预填的候选副本。

复制规则：

- 深拷贝 `PointsConfig.PointEntry`；
- 清空 `Id`，由新增结果生成新 GUID；
- 目标设备和分组来自当前树节点；
- 保留地址、类型、量程、说明、写入策略和风险等级作为预填值；
- 用户必须在弹窗中确认名称和地址；
- 保存时执行目标设备驱动校验和重复地址校验。

剪切规则：

- 只允许同设备目标；
- Paste 前原点位保持不变；
- Paste 成功后只修改同一个点位的 `GroupId`/`GroupCode`，不改变 `PointId`；
- Paste 失败或用户取消后原点位和剪贴板保持不变；
- 成功后清空 Cut 剪贴板；
- Copy 剪贴板成功粘贴后可以保留，允许再次粘贴。

```csharp
    PointsConfig.PointEntry? Candidate,
    DevicePointImportOperationKind Operation,
    IReadOnlyList<string> Issues);

public sealed record DevicePointImportPlan(
    string SourceRevision,
    string SourceCatalogFingerprint,
    IReadOnlyList<DevicePointImportPlanRow> Rows,
    IReadOnlyList<PointsConfig.PointEntry> MergedPoints)
{
    public bool CanApply => Rows.Count > 0
        && Rows.All(row => row.Operation != DevicePointImportOperationKind.Conflict);
}

public sealed class DevicePointImportPlanner
{
    public DevicePointImportPlan Build(
        IReadOnlyList<DevicePointImportRow> importedRows,
        IReadOnlyList<PointsConfig.PointEntry> currentPoints,
        IReadOnlyList<PointsConfig.PointGroupEntry> currentGroups);
}
```

匹配顺序必须固定：

1. 有效 `PointId` 且设备归属一致；
2. 同设备 + 点位编码；
3. 同设备 + 解析后的点位标签；
4. 没有匹配则新增；
5. 跨设备相同编码、同设备重复规范化地址或身份不一致则冲突。

`Candidate` 的生成规则：

- 先深拷贝 Existing 或创建新对象；
- 只覆盖 v5 模板承载的字段；
- 重新写入已解析的 DeviceId、DeviceCode、GroupId、GroupCode；
- 已有可写点保留 `RiskLevel`；
- 已有点保留 `WritePolicy` 和 `DecodeOptions`；
- 新点使用新的稳定 Id；
- 所有点最后仍经过 `DevicePointImportValidator` 和完整快照校验。

`DevicePointImportPreviewViewModel` 不再自行执行匹配和等价判断，只消费 `DevicePointImportPlan.Rows`。最终 Apply 直接使用同一 Plan 的 `MergedPoints`，从结构上保证“预览什么，就应用什么”。

`DevicePointManagementViewModel` 增加幂等方法：

```csharp
public void ActivateRuntimeObservation();
public void DeactivateRuntimeObservation();
```

View 在 Attached/Detached 时调用，并订阅/取消订阅 `DeviceModes.StateChanged`。事件触发后只刷新：

- `ActiveRevisionText`；
- 当前设备状态；
- 当前通道聚合状态；
- 详情卡片颜色和文字。

不得重建树或清空点位清单。

#### E6. 完成条件

- 单点读取确实调用 `ReadFreshAsync`；
- 不创建第二套串口/TCP 会话；
- 旧 Revision 或旧运行时结果不会覆盖新页面状态；
- 一个点读取失败不阻断其他通道；
- 取消后不再更新未完成点位；
- 试验运行中不发送 Fresh 诊断请求；
- Simulation 明确显示为仿真，不声称现场硬件正常。

## 10. 人工验收脚本

### 10.1 操作反馈

1. 新增一个合法点位，确认显示成功；
2. 新增重复地址，确认显示明确失败；
3. 连续快速点击保存两次，确认只生成一个 Revision；
4. 制造配置应用失败，确认 ActiveRevision 不变；
5. 在活动试验中尝试保存，确认被拒绝。

### 10.2 复制、剪切和移动

1. 复制点位到同一分组，修改名称后保存；
2. 确认源点位仍存在且新 PointId 不同；
3. 再次粘贴同一个 Copy，确认生成第三个不同 PointId；
4. Cut 一个点位，取消 Paste，确认源点位仍存在；
5. Cut 后粘贴到同设备其他分组，确认只改变分组；
6. 尝试 Cut 到其他设备，确认拒绝；
7. Copy 到其他设备，输入不符合目标驱动的地址，确认不能保存；
8. 使用键盘完成复制、粘贴、删除确认和编辑。

### 10.3 导入和导出

1. 在根、通道、设备、分组四种范围分别导出；
2. 核对导出点位数量和标签前缀；
3. 修改一个普通点位并重新导入，确认 Preview 为更新；
4. 导出并导入一个已有高风险点位，确认风险等级未降低；
5. 导入一条重复地址，确认 Preview 为冲突且不可应用；
6. 打开 Preview 后在另一操作中修改配置，再确认旧 Preview，确认被拒绝；
7. 取消 Preview，确认没有新 Revision；
8. 确认导出文件中没有 PointId、DeviceId、实时值和质量。

### 10.4 点位诊断

1. 打开单点诊断，确认显示值、质量、时间和仿真标识；
2. 执行范围读取，确认进度递增；
3. 注入一个 Bad 和一个 Stale 点，确认分别显示；
4. 读取过程中应用新配置，确认旧返回不覆盖新状态；
5. 读取过程中取消，确认剩余点不再更新；
6. 活动试验期间尝试 Fresh 读取，确认被禁用；
7. 确认没有创建第二个串口/TCP 连接；
8. 对未实现 Hardware 驱动只显示故障/未实现，不显示硬件在线。

### 10.5 显示环境

至少人工检查：

- 1152×720、100% 缩放；
- 1920×1080、125% 或 150% 缩放；
- 长通道名、长设备名、长点位名；
- 中文输入法；
- 键盘和右键操作；
- Windows 当前目标环境；
- UOS/Linux 只有实际运行后才能记录为通过。

必须同时满足：

- 主页面视觉布局未被重新设计；
- 所有可见动作均有真实功能或明确不可用原因；

- 配置失败不污染 Active Revision；
- 活动试验锁有效；

- Preview 与最终 Apply 完全一致；
- 高风险和高级字段不会被简化模板静默覆盖；
- 当前范围导出可被导入器读取；
- 诊断读取使用当前运行时并丢弃旧版本数据；
- Core、App、Integration 全部通过；
- Headless 正常退出并生成有效 TRX；
- 人工 UI 脚本通过；
- Git 变更范围可解释且未覆盖用户已有修改。

### 11.2 只能判定为软件或仿真完成

即使所有自动化测试通过，下列内容仍不能宣称完成：

- 真实 Modbus TCP 读取或写入；
- 真实 Modbus RTU 串口通信；
- 真实 Siemens S7 通信；
- 现场断线和重连；
- UOS/Linux 兼容；
- 真实 PLC/仪表写入；
- KEPServerEX 或 OPC 客户端联调。

这些必须在对应环境单独验收。

## 12. 真实硬件驱动的后续准入条件

真实驱动编码前必须取得：

1. 设备准确型号；
2. 固件版本；
3. 通信模块型号；
4. TCP/IP、串口、站号和超时参数；
5. 官方地址和数据类型手册；
6. 一个已知值只读点；
7. 一个经现场书面允许的写入测试点；
8. 断线、重连和设备停机预期；
9. Windows/UOS 目标环境；
10. 第三方库完整开源、免费及依赖许可证核验结果。

取得以上信息后另建驱动实施计划，修改范围预计包括：

- `IDeviceDriver`/驱动工厂边界；
- `DeviceSession.StartAsync`；
- Modbus TCP/RTU 或 S7 具体运行时；
- 批量读取和类型解码；
- 写入、超时、重连和释放；
- 设备支持矩阵；
- 真实硬件集成测试。

不得为了让页面显示“在线”而把未实现驱动改成 Simulation，也不得把地址格式校验通过当成通信完成。
