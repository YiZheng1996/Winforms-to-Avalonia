## 3. 范围解析：一个来源，多个用途

### 3.1 当前入口与目标文件

当前 `DevicePointManagementViewModel.cs` 中的 `GetVisibleEntries`、`GetCurrentTemplateDevices`、`ResolveDeviceId`，以及 `.Diagnostics.cs` 的 `GetDiagnosticsEntries`、`.Export.cs` 的 `CreateCatalogExportRequest` 是收敛对象。

在 App/ViewModels 新增 `DevicePointManagementViewModel.Scope.cs`，只放范围解析、当前范围快照和范围能力，不引入 Core 对 Avalonia 类型的依赖。

建议数据契约（均为拟新增，不是已有接口）：

```csharp
internal sealed record DevicePointScopeSnapshot(
    string NodeKey,
    string DisplayName,
    bool IsEditable,
    bool CanDiagnose,
    IReadOnlyList<DeviceConfig.DeviceEntry> Devices,
    IReadOnlyList<PointsConfig.PointGroupEntry> Groups,
    IReadOnlyList<PointsConfig.PointEntry> Points);
```

实施要求：

1. 解析器输入完整设备/分组/点位快照和选中节点，输出只读集合；此时不克隆每个 PointEntry。输出不得交给编辑器直接修改。
2. 在选中树节点或生效配置快照变化时重建 `_currentScope`；点位搜索只筛选表格，不改变 `_currentScope`。
3. `CanExportCurrentRange`、`CanOpenDiagnostics`、`CanReadCurrentScope` 使用快照计数和运行时条件，不在 getter 中构建导出请求、克隆列表或访问数据库。
4. 用户执行导出、复制、导入计划构建时才生成不可变候选/克隆，保持 UI 快照与写入候选分离。
5. 范围内设备集合独立于点位数量。空设备可下载模板；没有点位的范围不可导出点位或读取点位。

### 3.2 固定范围合同

| 选择 | 表格点位集合 | 模板 | 数据导出/诊断 |
|---|---|---|---|
| Root 或尚未选择节点的初始全部范围 | 全部配置点位 | 当前已配置且有有效通道的设备 | 数据导出保留全目录；诊断只执行当前运行时存在的目标，缺失目标显示未执行原因 |
| 有效 Channel | 归属该通道的设备点位 | 通道中的有效设备 | 与同范围集合一致 |
| 有效 Device | 该设备全部点位，含未分组点位 | 该设备 | 与同范围集合一致 |
| 有效 Group | 同设备且属于该分组的点位 | 该设备，默认分组为当前选择 | 与同范围集合一致 |
| 虚拟节点/孤立设备节点 | 延续当前管理页不展示可操作点位的行为 | 禁用 | 禁用；孤立设备仍允许修复设备配置 |

兼容规则：有效稳定 Id 优先；仅缺少 Id 时才按已有明确的 Code 映射兼容。不得在 Id 已存在但冲突时用 Code 偷偷匹配另一对象。GroupCode 回退必须限定同一设备；DEFAULT 显示为“未分组”，不是跨设备公用分组。含孤立配置的 Root 导出不得静默删除问题点位；解析失败应展示问题并拒绝误导性的部分导出。

顶部“读取当前范围”、导出、模板和范围诊断均跟随树范围，不跟随右侧文本过滤。提示中写明“当前范围共 N 个点位”；右侧搜索仍只影响表格数量。单点诊断只处理指定行，不改变树。

## 4. 页面操作所有权、命令与状态通知

### 4.1 修复 F05 并统一显式操作

修改 `DevicePointManagementViewModel.Operations.cs`：

1. `WaitAsync(0, ct)` 失败时返回“已有设备配置操作正在执行，请稍候”，不得清除 `IsBusy`，不得释放未取得的锁。
2. 只有 `entered==true` 的调用设置忙碌、清除忙碌、释放锁并通知状态；取消发生于取得锁之前时也遵循此规则。
3. 把页面显式异步工作统一经过一个 `RunPageOperationAsync` 核心；`RunMutationAsync` 可以保留薄包装以减少变更，不再自己拥有另一套锁。
4. 纳入：加载/手动刷新、配置变更、导入解析、导入应用、模板下载、导出、主页面连接测试、主页面手动读取。定期缓存刷新不取得此锁，也不更改 `IsBusy`。
5. 将 `LoadAsync` 的实际读快照工作提取为无门的 `LoadCoreAsync`。其他已持门操作需要加载时直接调用 Core 方法，禁止嵌套调用再次取门的公共入口。
6. 文件选择/编辑/导入预览等待用户期间不持有页面操作锁；确认后重新校验当前快照、权限和能力。对话框显示所需的防重复状态独立于通信/配置操作锁。
7. 统一出口返回 `OperationFeedback`；不根据 `StatusMessage.StartsWith(...)` 判断成功失败。`RefreshAsync` 返回加载动作的真实结果。

核心控制流示例（表达所有权约束，按现有返回类型落地）：

```csharp
var entered = false;
try
{
    entered = await _pageOperationGate.WaitAsync(0, ct);
    if (!entered) return BusyFeedback();
    IsBusy = true;
    NotifyOperationStateChanged();
    return await action(ct);
}
catch (OperationCanceledException) { return CancelledFeedback(); }
finally
{
    if (entered)
    {
        IsBusy = false;
        _pageOperationGate.Release();
        NotifyOperationStateChanged();
    }
}
```

页面门仅管理本页并发；跨页面诊断/试验启动/配置应用仍由共享 `DeviceOperationCoordinator` 管理。

### 4.2 状态通知合同

`PageViewModel.IsBusy` 当前只是 `SetProperty`，不是本类 `[ObservableProperty]` 生成属性。不要添加一个不会被调用的 `partial OnIsBusyChanged` 期待生效。通过统一操作门集中通知，必要时在本类覆盖 `OnPropertyChanged` 处理本类依赖；不无故修改全部页面的基类行为。

通知集合：

| 触发原因 | 必须更新 |
|---|---|
| IsBusy 改变 | 所有 CanAdd/CanEdit/CanDelete/CanCopy/CanCut/CanPaste/CanMove/CanDownload/CanExport/CanRead/CanTest；相关命令 NotifyCanExecuteChanged |
| 树范围改变 | `_currentScope`、表格、分组目的地、模板描述、RuntimeStatusText、ScopeDetailsModeText、连接测试能力、诊断能力、事件日志范围 |
| 选中行改变 | 行动作、移动目标、单点诊断；不得重复重建整个树 |
| 运行时引用或状态改变 | 配置状态、运行状态、设备模式、读取/测试能力、缓存值和质量 |
| 复制/剪切载荷改变 | 粘贴和移动能力 |

`CanEdit` 保留权限含义，不把它与忙碌混成一个永久访问权；操作能力在权限之外叠加非忙碌、有效范围等条件。XAML `IsEnabled` 与命令 `CanExecute` 必须同源，直接调用方法仍执行校验，不能只依赖按钮变灰。

## 5. 复制、量程、剪切和移动

### 5.1 F01：复制量程

修改 `DevicePointDialogViewModel.Clipboard.cs` 的粘贴构造函数，在数据类型、驱动能力与 `InitializeModbusFields` 最终确定之后恢复量程：

- 原点位数值型且四个 `Effective*` 量程完整时，保留四个值并设置 `IsScalingEnabled=true`。
- 原点位没有量程时保持关闭，不把空值转换成 0。
- 目标协议/区域类型不支持数值换算时禁止启用；若复制因目标类型不兼容而改变语义，显示验证错误要求用户明确调整，不能静默丢弃量程。
- 部分量程的异常旧数据在粘贴校验中明确提示，不悄悄变成无量程。普通保存仍走现有校验。
- 新增/编辑/复制共用 `InitializeScalingFromPoint` 一类帮助方法，避免两个构造函数分别维护。切换为非数值类型的关闭/清空行为仍由现有类型规则统一处理。
- 保留目标设备和目标分组，复制生成新 PointId/Code；原点位不变。保留数值类型、地址结构、设备级 Modbus 数据排列、读写权限、风险等级、写入策略和备注，不只测量程。

### 5.2 A01：剪切只移动

`ApplyPasteAsync` 的 Cut 分支只更新 GroupId/GroupCode，这是正确业务语义，必须让界面与之匹配：

1. `PastePointAsync` 对 Copy 继续打开编辑器；对 Cut 使用现有确认弹窗展示“源设备/分组 → 目标设备/分组”，不显示可编辑名称、地址、数据类型和量程。
2. 明确目标选择来源：树选中分组即该组；树选中设备即该设备“未分组”。若需要选择其他组，先选树或使用“移动到其他分组”。
3. 在 ViewModel 提取以稳定源 PointId、目标 DeviceId、GroupId 为输入的移动方法；右键移动与剪切共用该方法。最终仅变更所属组，保留其他字段和身份。
4. 拒绝跨设备剪切，提示“跨设备请使用复制”；源点位已删除、源设备变化、目标组失效时拒绝并保留载荷。
5. 相同目标组返回“点位已在该分组”，不保存新 Revision；可保留剪切载荷让用户重新选择。
6. 只有成功移动后清除剪切载荷；取消、校验失败、保存失败均保留。Copy 成功后继续保留复制载荷以支持多次粘贴。
7. 右键移动补充“未分组”目的地；只排除当前分组，不再一律过滤 DEFAULT。使用真实目标组 Id，不把文字“未分组”当作标识。
8. `CreateClipboardPayload` 当前连续 Clone 两次；改为只克隆一次并先保存源身份。不可为了减克隆共享原始可变 PointEntry。

## 6. 实时监视、选择恢复与生命周期

### 6.1 周期缓存刷新

新增 `DevicePointManagementViewModel.Monitoring.cs` 或扩充现有 `.Diagnostics.cs` 后再迁移到该文件；建议集中管理，不在视图和 VM 各建一个计时器。

- 使用 Avalonia `DispatcherTimer`，默认 500 ms。仅页面附着期间启动；配置模式也更新轻量状态，只有实时监视模式刷新点位值。
- `ActivateRuntimeObservation` 幂等：订阅一次、启动一次并立即刷新。`DeactivateRuntimeObservation` 幂等：停止、退订并使排队回调失效。
- 计时回调在 UI 线程执行，不能调用 `ReadAsync`/`ReadFreshAsync`/`ReadManyFreshAsync`，不能创建连接。
- 将缓存刷新核心保留为可直接驱动的内部方法，测试不依赖真实等待 500 ms。生产计时器调用同一方法。
- 树范围变化、点位搜索变化、切换实时监视时立即刷新当前行；刷新沿用现有 `DevicePointRow`，不 Clear 表格或 RebuildTree。
- 一轮刷新先捕获运行时引用和 Revision。可用缓存必须属于当前 PointId/DeviceId/Revision；连接代次可获得时核对当前设备状态。运行时已替换、缓存失效或字段不匹配时清掉旧值并显示“未读取/数据已失效”，不得保留旧 Good 值。
- 遵循 `TryGetCachedValue` 和运行时质量契约；先检查 DeviceSession 的 Stale 判断，已有逻辑负责时不在 UI 另造一套超时阈值。需要处理没有缓存的情况。
- 不在每个 Tick 弹窗。异常记录日志，页面用状态提示；相同失败合并，恢复后正常刷新。
- 运行状态摘要仅在实际值变化时通知，避免每 500 ms 全量刷新所有配置属性。

### 6.2 视图生命周期

`DevicePointManagementView.axaml.cs` 现有 Attached/Detached 之外，处理已附着视图的 DataContext 替换：先停止旧 VM，再启动新 VM。排队回调验证观察代次/当前附着状态，不能在离开页面后继续修改集合。

`DeviceEventLogViewModel` 取消构造函数内自动 Attach，由页面唯一负责 Attach/Detach；外部直接用该 VM 的测试同步迁移。Detach 后已排队的 EventReceived 回调必须检查 `_subscribed` 或代次。连续事件合并为一次待处理 UI 刷新；收起时暂停重建可视集合，展开时从快照补齐。

### 6.3 A02：双表格选择恢复

为实时监视表格指定明确名称（例如 `LivePointGrid`）。`ScrollSelectedPointIntoView` 根据当前模式选择可见表格；排队执行时再次核对 DataContext、选中 PointId 和页面附着状态。配置/监视共用选中对象，切换不丢失选中行，不滚动隐藏表格。

## 8. 统一手动通信安全入口

### 8.1 选定实现路线：共享门控，原连接测试器不再自行取门

当前事实：

- `DeviceOperationCoordinator` 已有 `EnterExecutionAsync`、`EnterConfigurationAsync`、`EnterDiagnosticsAsync`，都是同一个 SemaphoreSlim。
- `TestExecutionService.StartAsync` 在启动事务期间持有 Execution 门；不能据此认为整个试验期间一直占门。
- 三个连接测试器目前各自持有 Diagnostics 门，但不查询活动试验；页面和编辑器回调也没有覆盖所有入口。

新增 Core/Application 的 `DeviceManualOperationGuard`（拟新增名称），依赖同一个 `DeviceOperationCoordinator` 和 `IRecordRepository`，提供泛型执行方法：

```csharp
Task<T> ExecuteAsync<T>(Func<CancellationToken, Task<T>> operation,
                       CancellationToken ct = default);
```

行为：先异步检查活动试验快速拒绝 → 取得 Diagnostics 门 → **在门内再次检查活动试验** → 执行动作 → finally/await using 释放。查询失败按失败处理，不当作没有活动试验；传递 ct，禁止同步 `GetAwaiter().GetResult()`。等待过程中取消不得执行设备动作。持锁执行的动作禁止再取得同一个协调器。

### 8.2 连接测试唯一门控位置

1. 新增 `GuardedDeviceConnectionTester : IDeviceConnectionTester`，内部依赖 Guard 和现有 `CompositeDeviceConnectionTester`。
2. 生产组合根把 S7/TCP/RTU 原始测试器组成 Composite，再包一层 Guarded，注入 `ShellServices.DeviceConnectionTester`。页面与设备编辑器只能拿到该受保护实例。
3. 删除三个原始测试器内部的协调器字段/取门逻辑和对应构造参数，更新生产及测试调用。原始测试器只负责连接参数、驱动握手、资源释放和 RTU 串口租用判断。不得保留外层/内层双重锁。
4. 保留 RTU `_isSerialPortLeased` 回调，检查在统一 Guard 所持锁内执行。连接测试始终只验证 TransportOnly，不读点位、不写点位、不保存候选配置。
5. Guard 拒绝返回可见“存在活动试验，禁止测试连接/手动读取”的业务错误。设备编辑器不再依赖可空且未接入的 `_hasActiveRun` 保证安全；删除该冗余回调后更新所有构造调用及测试。表单自身合法性校验仍保留。
6. 不向业务页面暴露裸连接测试器。生产组合测试必须断言两个界面共用受保护的同一服务。

### 8.3 手动读取唯一实现

新增 Core/Application 的 `DevicePointDiagnosticReader` 和不含 UI 类型的目标/结果 DTO（拟新增），使用同一个 Guard、当前运行时提供函数和现有 IDeviceRuntime。

读取合同：

- 主页面范围读取、诊断窗口范围读取、诊断窗口单点读取全部调用它；移除主页面直接 `ReadManyFreshAsync` 以及窗口内重复安全判断/校验算法。
- 先固化目标 PointId/DeviceId/ChannelId，取得 Guard 后再捕获当前 runtime、Revision 和设备连接代次。按目标验证运行时点位存在，不从新配置“猜”旧目标。
- 每个实际读取前后检查运行时引用/Revision；结果校验 PointId、DeviceId、Revision 和读取后当前连接代次。旧结果标记丢弃，不能写入“正常”行。
- 保留当前按通道分组、同通道串行、最多 4 通道并发的上限；可以复用现有算法，不在本轮改造设备底层批量规划。UI 更新通过 Progress/Dispatcher 回到 UI 线程，Core 不引用 Avalonia。
- 按实际 PointQuality 统计；Bad 不算成功，Stale 单列。一次失败不吞掉其余可读取结果；取消立即阻止后续排队目标，已完成结果保持真实状态。
- 运行配置变更后，页面从当前运行时缓存刷新，不使用旧服务结果覆盖新范围。
- `DevicePointDiagnosticsWindow` 任意关闭路径（标题栏关闭、按钮、Escape、owner 关闭）均取消读取；已有 Escape 取消逻辑不足以覆盖全部路径。
- 手动读取有有限等待：单点使用既有超时参数；通道并发受上限限制；不无限等待不可取消任务。取消支持不足应返回失败并记录边界，不假报已取消。

### 8.4 注入与寿命

AppComposition 在创建共享 DeviceOperations、recordRepo、DeviceModes 后创建 Guard/Reader；若需要运行时引用，使用 `() => DeviceModes.Runtime`，不永久缓存旧实例。ShellServices 增加诊断读取服务依赖，并更新 AppTestHarness 和所有直接 new ShellServices 的测试。共享 Coordinator 由现有组合根统一释放；页面/弹窗只释放自己的 CTS、订阅和计时器，不 Dispose 共享服务。

## 10. 导入计划和校验管线

### 10.1 保留的职责边界

- `PrepareImportedPoints`、设备/分组解析、驱动校验：在同一个快照上执行并返回包含行号的标准问题。

### 10.2 编码步骤

1. 在 `.Import.cs` 提取不管理 IsBusy 的 `ParseAndValidateImportCoreAsync`，公共入口各取得一次页面门后调用。
2. 预览开始时先加载一个完整 Active snapshot，再使用该 snapshot 的 Device、Groups、Points 完成身份解析、驱动校验和 Plan 构建。不要先按旧页面设备解析、后按新 Active 点位构建 Plan。

6. 预览和确认应用共用同一个 Plan；SourceRevision 或目录指纹变化必须拒绝并要求重新预览。不得在确认时偷偷重建新计划再保存。
7. 无效/取消导入不保存；无变化计划返回无变化反馈，不无意义生成新 Revision。
8. 删除 `MergeImportedPoints` 和它专用的 VM `GetPointTag`。不得删除导入预览 VM 内另一个仍在使用的同名 GetPointTag。
9. 保留模板真实版本、列定义和协议能力来源，按当前 `DevicePointTemplateDefinition` 与描述器执行。此次不回退旧文档的列数，也不更改客户文件格式。

## 12. 结构与性能收敛

### 12.1 职责归属

- `DevicePointManagementViewModel.cs`：页面公开状态、初始化和协调；不继续累积解析算法。
- `.Scope.cs`：唯一范围快照与能力。
- `.Operations.cs`：页面操作门、结果和通知。
- `.Monitoring.cs`：计时器、缓存、运行时观察及生命周期。
- `.Clipboard.cs`：复制载荷、粘贴和移动。
- `.Import.cs`：导入管线适配与计划应用。
- `.Export.cs`：实际请求构建和文件导出；能力来自 Scope。
- `.Diagnostics.cs`：诊断服务适配和窗口模型创建，不再重复实现底层读取。
- 将管理 VM 文件开头的 `DevicePointRow` 移到同名文件；树构建如仍占据主文件大段，可移动到 `.Tree.cs`。这是移动既有实现，不复制第二份。
- 视图负责窗口、文件选择、菜单渲染、焦点与滚动；业务权限、范围、计划和通信门放 VM/Core。

### 12.2 性能改动边界

1. 创建 `_currentScope` 时建立设备/分组索引，避免每一行反复全表查找设备名称、组名和轮询周期；配置变化时重建索引。
2. `CanExportCurrentRange`/`CanOpenDiagnostics` 不深克隆、不枚举完整导出；能力 getter 无副作用。
3. `CreatePointRow` 与 `ReconcilePointRows` 当前可能对同一缓存行连续 UpdateFrom，收敛到一次。只有新数据改变时发属性通知。
4. 集合协调先构建目标 Id 集合/现有 Id 索引，再删除过期行、插入新行和移动必要行，保留行对象、选择和滚动。不要把同一实例误删后重建。
5. 明确 ObservableCollection.Move/Insert 本身仍可能产生 O(n) 成本；不得未经测量宣称整个算法严格 O(n)。本轮先消除多余扫描、重复 UpdateFrom 和能力 getter 深克隆。
6. 树搜索/点位搜索维持当前功能，计时器不重建搜索结果。事件日志合并 UI 刷新并保持现有最多 200 条显示，不扩展为新的持久化日志系统。
7. 100、1,000、5,000 点位分别记录首次加载、切换范围、搜索和缓存刷新耗时及分配；结果放任务输出目录。性能测量不设置依赖机器速度的脆弱单元测试阈值，重点断言无额外设备 I/O、无全表克隆、行对象复用。
