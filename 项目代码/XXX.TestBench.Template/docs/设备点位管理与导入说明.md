# 设备点位管理与导入

## 作用

设备点位是运行时读取数据的来源，和“试验项点”不是同一个概念：

- 设备点位：维护通信通道、设备、地址、数据类型、单位、量程和写入权限。
- 试验项点：维护产品类型下的试验名称、编译期执行器和执行顺序。
- 试验参数：维护项目、产品类型和产品型号级的业务参数。

当前模板以 config/device-config/active.json 指向的完整配置版本作为运行时来源；没有生效清单时才从根目录 v1 文件显式迁移，已有 v2 点位版本启动时会生成 v3 默认分组。左侧导航“设备点位”页（独立于参数管理，位于“设备与校准”之后）只维护通道、设备、分组和点位树，支持点位手工新增/编辑/删除、分组管理、点位移动、业务信号绑定、下载导入模板，以及按固定格式导入 xlsx / csv。

配置关系固定为“通信通道 → 设备 → 点位分组 → 点位”。点位分组是一层显示/筛选目录，不持有地址、驱动、实时值或 I/O 路由；点位地址唯一性仍只按“设备 + 驱动规范地址”判断。通道、设备和分组的编辑内容先停留在候选中，点击“保存并应用”后才通过统一配置服务生成新的 Revision。删除通道、设备或分组前必须解除设备、点位和信号绑定引用，不会静默级联删除。

## 编辑页面的字段含义

编辑页面面向客户显示的是“所属设备”“数据类型”和“写入权限”，不要求客户直接记忆内部配置值：

- 所属设备：点位只引用设备身份，设备再引用通道和驱动；修改设备名称不会改变设备 ID。点位页面不再直接选择真实协议。
- 所属分组：分组只用于树状组织和筛选，同一设备内分组编码唯一；删除分组前必须先移动或删除其中的点位。每个设备始终保留至少一个分组，旧点位会自动进入 DEFAULT/未分组。
- 通信方式：旧版兼容编辑器中的通信方式字段，告诉系统应该用什么方式解释下面的设备地址。完整 v2 编辑器以所属设备的 DriverKey 为准；真实协议必须先有对应设备驱动和现场配置，不能仅靠填写文字就生效。
- 数据类型：告诉系统如何解析设备值。常用选项包括开关量、小数、整数和文本；客户在页面或模板中只需要选择/填写中文值，系统会在边界处转换为配置文件和驱动使用的内部值。
- 写入权限：合并了原来的“可写”和“风险等级”，分为“只读”“可写（普通）”“可写（高风险）”。高风险表示写错可能引起启动、停止、复位或输出动作，不代表保存点位时会立即写设备。

写入权限只是点位的声明属性。实际写入仍必须通过权限、设备模式、连接与质量、活动试验状态、业务联锁、风险确认以及硬件回读等安全检查；界面不会绕过 DeviceWritePipeline 直接写协议设备。

## 导入列

页面“下载导入模板”生成 设备点位导入模板.xlsx，包含“点位模板”“填写说明”和“填写示例”三个工作表。客户可以先打开“填写示例”照抄一行，再回到“点位模板”填写真实数据；只有第一个工作表会被导入。

导入时必须使用该模板：第一个工作表名称必须为“点位模板”，第 1 行必须严格保持以下中文列名和顺序，不允许使用英文列名、增删列或调换顺序：

点位标识、点位编码、点位名称、设备编码、点位分组编码、地址类型、地址参数、原始数据类型、字节序、字序、单位、原始下限、原始上限、工程下限、工程上限、可写、启用、风险等级、说明。

必填数据：点位编码、设备编码、地址类型、地址参数、原始数据类型。点位分组编码可留空，系统按当前设备的 DEFAULT/未分组处理；填写时必须是该设备已经存在的分组，不会通过点表隐式创建设备或分组。点位标识在新增行可以留空；有值时必须与设备归属和点位编码一致。地址类型/地址参数必须使用模板示例中的驱动规范格式，不能把 40001 等手册地址未经确认直接当成零基协议偏移。可写和启用填写“是/否”，风险等级填写“普通/高风险”；留空时分别按“否”“是”“普通”处理。若可写=否，风险等级不能填写高风险。四个量程列必须全部填写或全部留空。Excel 和 CSV 都必须使用同一套中文表头；CSV 示例文件为 设备点位导入模板.csv。模板中的中文值会在导入时转换为运行时内部值，客户不需要填写英文内部值。

导入器会清理表头首尾空格和 UTF-8 BOM，但不会兼容英文表头、旧 18 列表头或其他列名变体。当前 v3 导入只执行“合并新增/更新”：按 PointId 更新，其次按“设备编码 + 点位编码”更新；分组变化会在预览中标记为“更新分组”；文件中没有出现的其他设备点位保持不变。跨设备编码冲突、未知设备、未知分组、归属与 PointId 不一致时在预览/校验阶段拒绝，不隐式创建设备或分组。

## 类型约束

点位通信方式和数据类型在核心模型中使用枚举管理：DevicePointProtocol、DevicePointDataType；仿真变化方式和故障行为也分别使用 SimulationChangePattern、SimulationFaultBehavior。设备驱动通过编译期注册表描述能力，当前只有 simulation 驱动已实现；modbus-tcp、modbus-rtu、siemens-s7 只登记为未实现驱动，启用前会被拒绝，不会自动回退仿真。配置文件仍保留稳定英文值，中文模板值只在导入边界转换一次。

## 保存规则

导入会先完成必填字段、设备归属、重复编码、同设备规范地址重复、驱动能力、量程完整性和上下限关系校验，并在页面显示新增/更新/冲突预览；用户确认后才调用完整配置应用服务，取消或校验失败时不保存。应用生成不可变 Revision 目录和清单哈希，通过 active.json 原子切换，随后重建整套设备运行时。运行中有活动试验时禁止修改设备配置和点位。

点位配置只声明数据，不会通过 Excel/CSV 生成或执行任意代码；真实 Hardware 通信仍需对应设备适配器、型号/协议手册和现场验收。当前测试只证明 Windows + Simulation 软件闭环，真实 Modbus/S7、硬件和 UOS 均未验证。
