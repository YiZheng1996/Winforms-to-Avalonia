# 设备点位管理与导入

## 作用

设备点位是运行时读取数据的来源，和“试验项点”不是同一个概念：

- 设备点位：维护通信通道、设备、地址、数据类型、量程和写入权限；点位一旦配置即参与运行。
- 试验项点：维护产品类型下的试验名称、编译期执行器和执行顺序。
- 试验参数：维护项目、产品类型和产品型号级的业务参数。

当前模板以 config/device-config/active.json 指向的完整配置版本作为运行时来源。左侧导航“设备点位”页（独立于参数管理，位于“设备与校准”之后）按配置关系显示“全部设备 → 通道 → 设备 → 已配置分组”，分组是叶子节点，具体点位只在右侧清单展示和操作。页面支持点位手工新增/编辑/删除、分组管理、点位移动、业务信号绑定、按当前树范围下载模板，以及按固定格式导入 xlsx / csv。左侧树只显示业务名称：例如通道名称为“PLC”时树中直接显示“PLC”，不拼接编码和显示名称；右侧点位清单支持右键操作，双击或按 Enter 可直接编辑选中点位。

运行时配置关系和客户树均固定为“通信通道 → 设备 → 点位分组 → 点位”，因为通道是 TCP/串口等共享连接资源的生命周期所有者；同一通道被多个设备引用时只在树中出现一次，并在通道摘要中标明共享设备数。点位分组是一层显示/筛选目录，不持有地址、驱动、实时值或 I/O 路由。内部默认分组只用于配置归属，不生成“未分组”树节点、不作为客户界面文字；点击设备节点即可看到该设备的全部点位，点击业务分组只显示该分组点位。未关联有效通道的设备统一放在“未关联通道（需修复）”下，修复前不能新增点位。点位地址唯一性仍只按“设备 + 驱动规范地址”判断。通道、设备和分组的编辑内容先停留在候选中，点击“保存并应用”后才通过统一配置服务生成新的配置版本。删除通道或设备前必须解除其引用及信号绑定；删除普通分组时经确认后点位仍保留在设备下，不会静默级联删除。

## 树节点操作

右键“全部设备”、通道、设备或分组，菜单只显示当前节点有意义的新增、编辑和删除操作，不再在左侧堆放一组随选中节点变灰的按钮。右侧点位清单右键某一行时，菜单只针对该行提供“编辑点位、移动到其他分组、删除点位”；空白处右键沿用当前树节点菜单。键盘用户可在选中节点后按 Shift+F10（或菜单键）打开相同菜单，页面同时提供可见的“新增”“新增点位”“更多”入口。活动试验、引用关系或配置服务限制等运行时条件仍由统一服务校验，并在页面状态栏说明原因。

## 页面清单显示

左侧树只承担设备层级导航和范围筛选：根节点、通道、设备和分组节点均只显示业务名称，通道/设备摘要可显示通信或驱动状态及点位数；具体点位地址不在左树展开。设备节点包含该设备的全部点位，未分组点位不单独生成节点。右侧清单只保留点位名称（第二行显示所属设备）、设备地址、数据类型、访问权限和操作；采集周期、量程/缩放、说明等详细配置在对应编辑页面查看，点位不再显示单位和启用状态，避免表头拥挤。

## 编辑页面的字段含义

通道和设备使用两个独立编辑窗口：新增/编辑通道只填写通道名称、连接方式及对应连接参数；新增/编辑设备只填写设备名称、所属通道、设备驱动及设备参数。通道编码、设备编码和内部 Id 由系统生成或沿用，不在客户界面显示或要求填写。

点位编辑页面面向客户显示的是“所属路径”“点位名称”“设备地址”“数据类型”和“写入权限”，不要求客户维护内部编码、单位或启用状态字段；点位保存后固定按已配置点位参与运行：

- 点位标签/名称：单设备编辑时填写 `分组.点位`，例如 `AI.进气压力`；不分组时直接填写 `进气压力`。跨设备模板才使用 `设备编码/分组.点位`，用于确定点位属于哪台设备。分组只用于分类，不改变设备地址。
- 截图中的 `AI`、`AO`、`DI`、`DO` 等目录在本项目对应“点位分组”前缀；真正的 TCP/串口通信通道仍在设备配置层维护，不放进点位标签，避免把分类目录误当成连接资源。
- 所属设备：点位只引用设备身份，设备再引用通道和驱动；修改设备名称不会改变设备 ID。设备驱动、IP/串口、站号和轮询周期在设备/通道编辑中配置。
- 所属分组：分组只用于树状组织和筛选，同一设备内分组编码唯一；删除普通分组时先确认，再把其中点位保留在设备下。客户可以不创建业务分组，未分组点位直接在设备节点的点位清单中维护。
- 设备地址：直接填写该设备驱动要求的原始地址。系统按设备驱动、型号或 CPU Profile 做格式和数据类型预校验；格式不匹配时不能进入导入确认。
- 数据类型：告诉系统如何解析设备值。常用选项包括开关量、小数、整数和文本；客户在页面或模板中只需要选择/填写中文值，系统会在边界处转换为配置文件和驱动使用的内部值。
- 采集周期：点位清单显示所属设备的采集周期，标记为“设备配置”；它不是点位独立参数，需要在设备编辑器中调整，避免同一设备的点位填写出互相矛盾的扫描速率。
- 写入权限：页面分为“只读”“读写”两种声明；高风险等级仍由既有配置和运行时安全链保留，不通过简化模板新建高风险点位。单位和点位启用状态不属于当前点位配置界面和导入模板。

点位标识、点位编码、设备标识和分组标识仍保留在运行时模型/JSON 中，它们是系统维护的稳定关联键：用于保留信号绑定、迁移旧配置、精确更新和诊断，不要求客户在新模板中重复填写。设备编码和分组编码只在导入边界用于解析跨设备标签，解析完成后转换为内部 ID；显示名称也不再和编码拆成两列，统一由点位标签/名称承担客户输入和查找职责。

写入权限只是点位的声明属性。实际写入仍必须通过权限、设备模式、连接与质量、活动试验状态、业务联锁、风险确认以及硬件回读等安全检查；界面不会绕过 DeviceWritePipeline 直接写协议设备。

## 导入列

页面顶部的“更多 → 下载模板”直接使用左侧当前树范围：根节点导出全部设备，通道节点导出通道下全部设备，设备或分组节点导出对应设备。生成的设备点位导入模板.xlsx 会按当前范围准备设备下拉项、通信方式可选项和填写示例；包含“点位模板”“填写说明”和“填写示例”三个工作表。客户可以先打开“填写示例”照抄一行，再回到“点位模板”填写真实数据；只有第一个工作表会被导入。

导入时必须使用该模板：第一个工作表名称必须为“点位模板”，第 1 行必须严格保持以下中文列名和顺序，不允许使用英文列名、增删列或调换顺序：

点位标签、地址、数据类型、字节序、字序、访问权限、原始下限、原始上限、工程下限、工程上限、说明。

必填数据：点位标签、地址、数据类型。点位标签按当前模板范围填写：单设备范围使用“分组.点位”或未分组的“点位名称”，多设备范围使用“设备编码/分组.点位”。填写的分组必须已经存在于对应设备下，不会通过点表隐式创建设备或分组。Modbus 地址首选 `C:0`、`DI:0`、`HR:0`、`IR:0`，不能填写无法确定数据区的裸数字；S7-1500 可填写 `DB144.DBD88`，S7-200 可填写 `VW5022`。Modbus 的字节序填写“大端/小端”；Int16/UInt16/Bool 的字序填写“无”，Int32/UInt32/Float32/Double 必须填写“高字在前/低字在前”。空字节序按“大端”初始值进入预览并标记来源，旧 v5 模板的多寄存器 Modbus 点位因缺少字序会被拒绝。访问权限填写“只读/读写”。四个量程列必须全部填写或全部留空；单位和启用状态不属于当前模板，导入的新点位固定参与运行。Excel 和 CSV 都必须使用同一套中文表头；CSV 示例文件为 设备点位导入模板.csv。模板中的中文值会在导入时转换为运行时内部值，客户不需要填写英文内部值。

导入器会清理表头首尾空格和 UTF-8 BOM，但不会兼容英文表头或其他列名变体。当前版本优先接受 v6 固定 11 列；旧 v5 固定 9 列仅作兼容读取，字节序按项目初始值“大端”，多寄存器 Modbus 点位因缺少字序直接拒绝。列数、列名或顺序不一致的其他模板拒绝，不进入数据解析。导入只执行合并新增/更新：按当前设备范围和点位标签查找已有点位，点位标签变化会作为新标签写入同一条配置记录或按现有匹配规则新增。文件中没有出现的其他设备点位保持不变。多设备模板缺少设备前缀、未知设备、未知分组、地址格式与设备驱动不匹配、同设备地址重复时，在预览/校验阶段拒绝，不隐式创建设备或分组。

## 参考 KEPServer CSV 的整理方式

附件 `Inverter.csv` 是 KEPServer 风格的英文参考表，不是本项目可直接导入的文件。项目保留相同的核心信息，但将表头和填写值统一为中文，并把不属于点位层或当前运行时尚未支持的字段明确放在设备配置/后续能力边界内：

| 参考字段 | 项目中文模板 | 处理规则 |
| --- | --- | --- |
| Tag Name | 点位标签 | 直接整理为 `分组.点位`；跨设备模板使用 `设备编码/分组.点位`，不再拆成客户填写的编码和名称两列。 |
| Address | 地址 | 直接保留设备地址原文；Modbus 优先使用 `C:0`、`DI:0`、`HR:0`、`IR:0`，明确功能区的 00001/10001/30001/40001 只在导入边界规范化；S7 仍由对应驱动校验。 |
| Data Type | 数据类型 | 按设备手册从中文选项中选择，不能把 `Word` 等泛型名称直接等同为某一种有符号类型。 |
| Byte Order / Word Order | 字节序 / 字序 | Modbus 寄存器点位按设备手册填写大端/小端及多寄存器高字/低字顺序；空字节序使用项目初始大端并在预览标记来源，旧 v5 多寄存器点位没有字序时拒绝导入。 |
| Respect Data Type | 无直接对应列 | 项目运行时始终按已选择的数据类型解析，不增加绕过配置的开关。 |
| Client Access | 访问权限 | `R` 对应只读，`R/W` 对应可写（普通）；启动、停止、复位、输出等点位仍需标为可写（高风险）。 |
| Scan Rate | 设备配置中的采集周期 | 不在每个点位重复填写；点位清单只读显示所属设备的周期。 |
| Scaling、Raw/Scaled Low/High | 原始下限、原始上限、工程下限、工程上限 | 四项完整填写时按线性量程换算；缺一项则不启用量程。 |
| Scaled Data Type | 无直接对应列 | 当前运行时没有独立的工程数据类型，使用原始数据类型作为解析类型。 |
| Clamp Low/High | 暂不支持 | 当前模型和运行时没有限幅语义，不导入、不导出。 |
| Eng Units | 不配置工程单位 | 当前 11 列模板不包含工程单位；单位不由点位编辑和导入流程应用。 |
| Description | 说明 | 直接填写点位用途、来源或现场备注。 |
| Negate Value | 暂不支持 | 当前模型和运行时没有取反语义，不导入、不导出。 |

因此，KEPServer 英文 CSV 需要先人工整理到本项目下载的中文模板中，再通过页面的“导入点位”校验和预览；不会按列名猜测真实协议地址，也不会把暂不支持的字段伪装成已经生效的配置。

## 参考 KEPServer JSON 的对应关系

附件 `发动机试验台OPC-控制.json` 进一步确认了点位层级：`PLC / StartPLC / 被试品端电量测量` 是通信通道，下面的 `S71500 / S7200 / Value1` 是设备，设备下的 `AI / AO / DI / DO / Fault` 等 `tag_groups` 是分类目录，目录下的 `tags` 才是具体点位。因此项目页面采用“全部设备 → 通信通道 → 设备 → 已配置分组”，分组下不再展开具体点位，未分组点位随设备显示在右侧清单，而不是把 KEPServer 的 OPC Server 配置整体复制到上位机。

JSON 中的 `DEVICE_ID_STRING` 对应设备 IP/站号，`DEVICE_SCAN_MODE_RATE_MS` 对应设备级采集周期，`TAG_ADDRESS` 对应模板“地址”，`TAG_DATA_TYPE` 和 `TAG_READ_WRITE_ACCESS` 需要按驱动/类型规则转换为中文模板值。JSON 中的数字类型码不能脱离 KEPServer 版本直接当作项目数据类型；例如该文件中 S7-1500 的 `DB144.DBD88` 是浮点双字、`DB142.DBX22.3` 是位，S7-200 的 `VW5022` 是字、`VD800` 是双字，项目导入预校验会依据设备型号判断这些组合是否成立。

## 类型约束

点位通信方式和数据类型在核心模型中使用枚举管理：DevicePointProtocol、DevicePointDataType；仿真变化方式和故障行为也分别使用 SimulationChangePattern、SimulationFaultBehavior。设备驱动通过编译期注册表描述能力；simulation、siemens-s7、modbus-tcp、modbus-rtu 的描述器和运行时边界已接入，Modbus TCP/RTU 使用共享会话、超时失效和首个有效响应上线规则。真实 PLC、Modbus 设备和现场验收仍需在对应环境单独验证。配置文件仍保留稳定英文值和内部 ID，中文模板值只在导入边界转换一次。

## 保存规则

导入会先完成必填字段、设备归属、重复编码、同设备规范地址重复、驱动能力、量程完整性和上下限关系校验，并在页面显示新增/更新/冲突预览；用户确认后才调用完整配置应用服务，取消或校验失败时不保存。应用生成不可变的完整配置目录和清单哈希，通过 active.json 原子切换，随后重建整套设备运行时。运行中有活动试验时禁止修改设备配置和点位。

点位配置只声明数据，不会通过 Excel/CSV 生成或执行任意代码；真实 Hardware 通信仍需对应设备适配器、型号/协议手册和现场验收。当前测试只证明 Windows + Simulation 软件闭环，真实 Modbus/S7、硬件和 UOS 均未验证。

## 点位复制、粘贴与当前范围导出

点位清单支持右键和键盘两种等价入口：`Ctrl+C` 复制、`Ctrl+X` 剪切、`Ctrl+V` 粘贴、`Delete` 删除、`Enter` 编辑。复制和剪切只使用当前进程内存剪贴板，不写系统剪贴板或配置文件。复制粘贴由点位编辑器确认名称、地址和分组后生成新的稳定 PointId；剪切粘贴只允许同一设备内移动，应用成功前不会删除原点位，失败或取消时源点位和剪贴板保持不变。

导入/导出菜单提供“导入点位”“导出当前范围”“下载填写模板”三个入口。导出范围跟随左侧当前选择：全部设备、通道、设备或分组；导出文件使用同一条 v6 十一列模板合同，可被当前导入器重新读取。导出内容不包含内部 PointId、DeviceId、GroupId、风险等级、运行时值、质量或时间戳，不能替代完整配置 Revision 和 manifest 备份。

导入先通过统一计划生成新增、更新、更新分组和无变化行；预览和最终应用消费同一份 Candidate 和 MergedPoints。匹配顺序为稳定 PointId、同设备点位编码、同设备点位标签，跨设备编码冲突、同设备规范地址冲突和身份不一致会在预览中阻止应用。导入更新已有点位时保留模板未承载的写入策略、字节序、字序和可写点位风险等级；导入把点位改为只读时风险等级归一化为普通；新增可写点位默认普通风险，不能通过简化模板直接提升为高风险。预览后 Active Revision 或点位目录指纹变化时，旧计划会被拒绝，必须重新导入预览。

## 只读点位诊断

“更多 → 点位诊断”打开独立只读窗口，范围同样跟随左侧当前选择；单点右键“查看状态”可只诊断一个点位。诊断复用当前 DeviceModes.Runtime 和通道会话，按 PointId 调用 ReadFreshAsync，不创建第二套串口/TCP 连接，也不向设备写入。窗口显示当前值、质量、采样时间、状态和错误说明；同一通道严格顺序读取，不同通道最多四路并行，一个点失败不中断其他点。读取期间运行时引用、ActiveRevision 或连接代次变化时，旧结果会标记为已丢弃，不覆盖当前状态；存在活动试验时禁止发起 Fresh 读取。仿真模式会明确标注“不代表现场硬件正常”。

## 本轮验证边界

已通过的自动化证据包括 Core、App 和 Integration 测试；设备点位 Headless 用例单独运行时正常退出并生成 TRX，覆盖导入/导出菜单、点位诊断窗口、主页面渲染和既有布局检查。完整 Headless 套件在这台 Windows 环境的旧全页端到端/截图路径上存在间歇性 Blame 挂起，不能把该次运行记录为通过。真实 Modbus TCP、Modbus RTU、Siemens S7、PLC/仪表写入、现场断线重连和 UOS/Linux 仍需在对应环境单独验收。

## S7-1200 硬件接入（S7NetPlus）

设备驱动 `siemens-s7` 的 Hardware 模式现在由 `S7NetPlusDeviceRuntime` 接入，使用 MIT 许可的 NuGet 包 `S7netplus 0.20.0`，通过 TCP 102 的 S7comm over ISO-on-TCP 与 PLC 通信。该库是第三方实现，不是 Siemens 官方驱动；Siemens 官方 S7-1200 系统手册和 PUT/GET 手册仍用于确认 PLC 侧设置和协议边界。

硬件模式前置条件：PLC 必须允许远程伙伴 PUT/GET；TCP 102 可达；目标 DB 若使用 `DB144.DBD88`、`DB142.DBX22.3` 这类绝对地址，应按 PLC 程序确认 DB 布局、偏移、数据类型和优化块访问设置。运行时优先尝试 S7-1200/S7-1500 常见的 rack 0 / slot 1，再回退 rack 0 / slot 0；如果使用外部 CP，需要按实际硬件配置调整。

真实 S7 数据区必须使用确定的类型：`Boolean/Bool`、`Byte/Char`、`Int16/UInt16`、`Int32/UInt32`、`Float32`。旧仿真使用的 `Decimal` 不会被猜测为 Real 或整数；硬件模式会在连接前明确拒绝 Decimal 点，要求按 PLC 实际类型修改配置。读取和写入共享现有通道串行门，写入仍由 `DeviceWritePipeline` 执行权限、风险、版本和 ReadBackEqual 校验。

没有真实 PLC、端口、地址和测试点的机器只能完成地址解析、字节序/字序和编码解码自动化测试；不能把该结果外推为 S7-1200 现场读写通过。
