# 设备点位管理界面简化改造实施方案

> 状态：已实施；自动化验证完成，1152×720 人工截图验收待执行
>
> 基线日期：2026-09-08
>
> 适用项目：项目代码/XXX.TestBench.Template
>
> 本文性质：实施规格与验收记录；代码已按本文和 ADR-0012 落地，未完成的现场/人工证据仍明确列在“后续”。

## 1. 一页结论

本轮改造的目标不是删除底层安全设计，而是把客户不需要理解的内容从日常操作界面移走。

必须落地的结论如下：

1. 正确业务层级固定为：通信通道 → 设备 → 点位分组 → 点位。
2. 左侧树统一显示“全部设备 → 通道 → 设备 → 已配置分组”，分组是叶子节点，不再显示点位子节点；内部默认分组不显示。
3. 点位只在右侧清单中展示、选择和操作。
4. 新增、编辑、移动、删除成功后，不允许整棵树收缩；必须保留展开节点、当前范围、选中点位和列表位置。
5. 通道和设备分别使用独立编辑窗口；客户只填写业务名称和对应参数，内部 Id、编码、协议键等不展示。
6. 编辑点位时不同时承担“换设备”和“换分组”；移动分组使用右侧清单中的独立动作。
7. 分组编辑器只保留分组名称，说明放入可选区域；分组编码、Id、数字排序由系统维护。
8. 删除点位、分组、设备、通道前必须使用项目现有遮罩确认弹窗。
9. 通道、设备、点位的稳定 Id、引用校验、版本切换、写入安全链必须保留。
10. 第一阶段仍沿用完整配置原子应用，不以“局部刷新”为理由绕过 ActiveRevision 安全约束。

客户最终看到的是简洁操作，程序内部仍保持严格身份和安全校验。两者并不冲突。

## 2. 文档优先级与范围

### 2.1 文档优先级

当前资料中存在层级描述冲突，实施时按以下顺序执行：

1. 数据和运行时关系以 docs/decisions/0012-多设备多协议点位管理.md 为准：通道拥有设备，设备拥有点位。
2. 客户界面结构和交互以本文为准。
3. docs/设备点位JSON配置与树状界面编码设计方案.md 中“设备 → 通道”和“树内点位节点”的内容被本文替代。
4. docs/设备点位管理与导入说明.md 中与本文冲突的页面说明，在代码完成后同步修订。
5. 既有配置格式、稳定 Id 和运行时安全约束，不因界面文档变化而自动废弃。

### 2.2 本轮必须完成

- 修正左侧树层级。
- 删除树中的点位节点。
- 修正各层级的可用动作。
- 增加右侧点位搜索和明确的可见操作入口。
- 简化点位和分组弹窗。
- 保存后采用稳定键进行局部集合合并，并恢复交互状态。
- 补齐删除确认和失败回滚。
- 修正错误的单元测试，并补充 Headless 行为测试。
- 更新受影响的使用说明。

### 2.3 本轮明确不做

- 不实现 Modbus、S7 等尚未接入的真实驱动。
- 不改变设备写入安全策略，不降低高风险写入确认要求。
- 不删除 PointId、DeviceId、ChannelId、Revision 等内部字段。
- 不强制迁移已有点位 Code。
- 不在本轮更换导入文件格式。
- 不把分组元数据从 points.json 拆到新文件；这属于后续独立架构任务。
- 不以本机仿真结果代替现场硬件验收。

## 4. 目标信息架构

### 4.1 统一术语

| 客户术语 | 含义 | 内部身份 |
| --- | --- | --- |
| 通信通道 | 串口、IP 连接、仿真连接等可被设备使用的连接资源 | ChannelId |
| 设备 | PLC、仪表、从站或仿真设备 | DeviceId |
| 点位分组 | 当前设备下用于整理点位的文件夹 | GroupId |
| 点位 | 可读取或写入的具体信号 | PointId |

页面上显示客户名称。编码和 Id 只用于内部关联、导入、审计和诊断，不作为日常主标题。

### 4.2 目标树

~~~
全部设备
├─ 通信通道 A
│  ├─ 设备 1
│  │  ├─ 模拟量输入               12
│  │  └─ 数字量输出                8
│  └─ 设备 2
│     └─ 温度                      6
└─ 通信通道 B
   └─ 设备 3
      （未分组点位直接显示在右侧）
~~~

强制规则：

- 根节点名称使用“全部设备”，不显示“未分组”节点。
- 通道节点直接来自 DeviceConfig.Channels，每个 ChannelId 只出现一次。
- 设备只能放在其 ChannelId 对应的通道下。
- 分组只能放在其 DeviceId 对应的设备下。
- DEFAULT 只作为内部归属，不在树中显示；其点位直接归入设备节点的右侧清单。
- 已配置业务分组节点显示点位数量，但 Children 必须为空。
- 点位不再作为左侧树节点，只在右侧点位清单中显示。
- 点位名称、地址或点位内部代码的搜索放在右侧，不通过树节点表达。

### 4.3 异常旧数据的显示

界面不能为了兼容错误数据再次颠倒层级。

- 没有设备的通道仍正常显示，数量为 0，可新增设备、编辑或删除。
- ChannelId 为空或引用不存在通道的旧设备，放在根节点下的虚拟节点“未关联通道（需修复）”中。
- 虚拟节点只用于暴露问题，不写入配置。
- 异常设备只允许“编辑设备”，在重新选择合法通道前不允许新增分组或点位。
- 页面顶部显示一条明确提示，例如“有 1 个设备未关联有效通道，请先修复”。

保留：

- 页面标题。

删除或合并：

- 标题使用“设备层级”。

- 标题显示路径，例如“通道 A / 设备 1 / 模拟量输入”。
- 显示当前范围的点位总数。
- 增加独立搜索框，可匹配点位名称、地址和内部 Code。
- 主按钮只在设备或分组范围显示“新增点位”。
- “编辑、移动、删除”放在“更多”菜单，并在选中行后可用。
- 双击点位继续执行编辑。
- 右键菜单继续存在，但不能成为唯一入口。

## 6. 节点选择和动作矩阵

| 当前范围 | 右侧显示 | 主动作 | 更多动作 | 禁止动作 |
| --- | --- | --- | --- | --- |
| 全部设备 | 全部设备的全部点位 | 新增通道 | 导入、导出全部 | 直接新增设备、分组、点位 |
| 通信通道 | 此通道下全部设备的点位 | 新增设备 | 编辑通道、删除通道、导出 | 新增分组、直接新增点位 |
| 设备 | 此设备全部分组的点位 | 新增点位 | 新增分组、编辑设备、删除设备、导出 | 新增通道 |
| 点位分组 | 此分组的点位 | 新增点位 | 编辑分组、删除分组、导出 | 新增通道、设备 |
| 未关联通道虚拟节点 | 异常设备及修复提示 | 无 | 无 | 所有配置新增 |
| 异常设备 | 不显示可编辑点位 | 编辑设备 | 无 | 新增分组、点位 |
| 右侧点位行 | 当前点位 | 编辑点位 | 移动分组、删除点位 | 更换设备 |

动作生成必须只依据节点类型和有效归属，不允许使用“如果找不到设备就取第一个设备”之类的兜底。

建议将 GetTreeNodeActions 改为穷尽 switch。每一种节点类型的动作在一个分支内明确返回，避免多个 if 叠加出非法组合。

## 7. 右侧点位清单

### 7.1 固定列

为避免切换范围时表格跳动，本轮不做动态列显隐。列顺序固定为：

1. 点位名称（第二行显示所属设备名称）
2. 设备地址
3. 数据类型
4. 访问权限
5. 操作

具体修改：

- 把“点位标签”改为“点位名称”。
- DevicePointRow 增加 PointName，直接取 Entry.Name；名称为空时回退到 Entry.Code。
- PointTag 不再作为可见主列。
- 内部 Code 如需排障，只放在详情提示或工程模式，不与分组路径拼接显示。
- 点位清单和编辑弹窗均不显示单位、点位启用状态；已配置点位固定参与运行。
- 表格排序必须稳定；同值时使用 PointId 作为最终稳定排序键。

### 7.2 搜索

新增 PointSearchText，与 TreeSearchText 完全分离：

- TreeSearchText 只搜索通道、设备和分组。
- PointSearchText 搜索当前范围内的点位名称、地址和内部 Code。
- 修改 PointSearchText 只刷新右侧清单，不重建树。
- 清空搜索后恢复当前范围和排序，不改变树展开状态。
- 如果选中点位被过滤掉，只清除表格选择，不改变树选择；再次出现时可按 PointId 恢复。

### 7.3 空状态

按原因分别显示：

- 当前分组为空：“该分组还没有点位。”并显示“新增点位”。
- 搜索无结果：“没有符合搜索条件的点位。”并显示“清除搜索”。
- 当前设备停用：“设备已停用，现有点位可查看；启用设备后才能新增或应用。”
- 异常设备：“设备未关联有效通道，请先编辑设备。”

## 8. 点位新增和编辑弹窗

### 8.1 尺寸和滚动

DevicePointDialogWindow 调整目标：

- 默认 Width 720、Height 620。
- MinWidth 640、MinHeight 520。
- CanResize 设为 true。
- 在 1152×720、100% 缩放下，常用字段和保存按钮无需垂直滚动。
- 不通过缩小字体解决高度问题。
- 只有展开“高级设置”且空间不足时，才允许高级区域内部滚动。
- 底部保存、取消按钮固定可见。

### 8.2 常用字段

默认只显示：

| 字段 | 新增 | 编辑 | 规则 |
| --- | --- | --- | --- |
| 所属路径 | 只读 | 只读 | 显示通道 / 设备 / 分组，不显示 Id 或编码 |
| 点位名称 | 必填 | 必填 | 客户可理解的名称 |
| 地址 | 必填 | 必填 | 使用当前设备驱动校验与规范化 |
| 数据类型 | 必填 | 必填 | 只显示当前驱动 SupportedDataTypes |
| 写入权限 | 必填 | 必填 | 只读、普通写入、高风险写入三种客户选项 |
| 保存到分组 | 条件显示 | 不显示 | 有业务分组时可选择；没有分组时直接保留设备归属 |

从分组节点新增时，分组由上下文确定，不再显示分组下拉框。

编辑点位时：

- 所属设备不可改。
- 所属分组不可改。
- 移动分组必须返回清单使用“移动到分组”。
- PointId 和 Code 原样保留。

### 8.3 高级设置

使用默认折叠的“高级设置”：

- 量程转换开关。
- 原始下限、原始上限、工程下限、工程上限。
- 说明。

显示规则：

- Boolean、String 等非数值类型不显示量程。
- 未启用量程转换时，四个量程值全部写为 null。
- 启用量程后四个值必须完整，且上下限不能相等。
- 说明为空时不占用额外高度。

### 8.4 不再显示的字段

客户弹窗中删除：

- 设备 Id。
- 设备编码。
- 点位 Id。
- 点位编码。
- 点位标签复合语法。
- 分组编码。
- 单独协议选择。
- RawDataType。
- AddressDefinition。
- DecodeOptions。
- WritePolicy 内部枚举。

这些字段仍保留在结果对象和配置模型中，由上下文、驱动描述器或系统默认值生成。

### 8.5 内部身份生成

不得再用客户可编辑的显示路径作为稳定身份。

新增点位：

1. 生成新的 PointId，格式保持有效 GUID。
2. 生成内部 Code，例如 PT_ 加 PointId 的 N 格式。
3. Code 在全配置范围内检查唯一。
4. DeviceId、DeviceCode、GroupId、GroupCode 从当前上下文复制。
5. Protocol 从设备 DriverKey 推导。
6. RawDataType、AddressDefinition、DecodeOptions 由驱动描述器或既有默认转换生成。

编辑点位：

- 永远保留原 PointId。
- 本轮永远保留原 Code。
- 修改名称、地址、数据类型或量程不得改变信号绑定身份。
- 如果旧点位没有有效 Id，只能由兼容迁移路径补齐，不在普通编辑弹窗临时换身份。

DevicePointDialogResult 可以继续承载内部字段，但 ViewModel 不应要求客户输入这些字段。

## 9. 点位分组弹窗

### 9.1 可见字段

默认只显示：

- 所属设备：只读名称。
- 分组名称：必填。
- 说明：可选，放在“更多说明”折叠区。

删除客户输入：

- 分组编码。
- 分组 Id。
- 数字排序值。

### 9.2 系统生成规则

新增分组：

- GroupId 使用新 GUID。
- Code 使用 GRP_ 加 GroupId 的 N 格式，且在同一设备内唯一。
- SortOrder 使用当前设备最大值加 10。
- 名称在同一设备内不允许完全重复，比较时忽略首尾空格和大小写。

编辑分组：

- 保留 GroupId、Code 和 SortOrder。
- DEFAULT 分组不能改名、不能删除。
- 普通分组可以改名称和说明。

排序不通过数字输入完成。将来若客户确实需要排序，再增加“上移/下移”，本轮不增加拖拽或复杂排序器。

## 10. 删除与移动

### 10.1 统一弹窗

复用项目现有 ConfirmDialogWindow 和 MainWindow.ShowDialogWithOverlayAsync，不新建第二套确认组件。

所有危险动作都遵循：

1. 页面代码先收集影响信息。
2. 显示遮罩确认弹窗。
3. 客户确认后才调用 ViewModel 变更方法。
4. 取消时不修改集合、不修改状态消息为“成功”。
5. 后端引用校验仍是最终安全边界，不能只依赖弹窗。

### 10.2 点位删除

确认内容至少包括：

- 点位名称。
- 所属设备。
- 地址。
- 如果可写或高风险，明确显示“该点位允许写入”。
- 如果有信号绑定引用，不提供确认删除，直接提示先解除引用。

成功后：

- 保留当前树范围和展开状态。
- 选择同位置的下一行；没有下一行则选择上一行。
- 不跳回根节点。

### 10.3 分组删除

推荐客户语义：

“删除分组，并把其中 N 个点位保留在设备下。”

规则：

- DEFAULT 分组不可删除。
- 删除普通分组时，不静默删除其中点位。
- 确认后在一个候选快照中完成：点位 GroupId 改为当前设备 DEFAULT 分组，随后删除目标分组。
- 任一步校验失败，整个候选不应用。
- 成功后选择父设备，并在表格中保留原选中 PointId（如果原先选中了点位）。

### 10.4 点位移动

- 目标分组只列出当前点位所属设备的分组。
- 不列出当前分组。
- 不允许跨设备移动。
- 移动只修改候选副本的 GroupId 和 GroupCode。
- 不能对 _allEntries 中当前对象做原地修改。
- 应使用 ClonePoint 创建新 PointEntry，再替换候选集合中的目标项。
- 应用失败时，页面继续显示旧分组和旧生效版本。
- 应用成功后自动选择目标分组并重新选中该 PointId。

## 11. 局部刷新与状态保持

### 11.1 用户可观察的验收标准

无论内部是否重新生成配置快照，以下行为必须成立：

- 新增点位：父设备、父分组和其他已展开节点保持展开，新点位行被选中。
- 编辑点位：树不闪回根节点，当前行保持选中。
- 移动点位：切换到目标分组并选中新点位，其他分支展开状态不变。
- 新增分组：父设备保持展开，新分组被选中。
- 删除分组：选择父设备，不收缩其他分支。
- 新增设备：对应通道保持展开，新设备被选中。
- 新增通道：新通道被选中。
- 搜索和清空搜索：恢复搜索前的展开状态。
- 应用失败：树、表格和选中项保持原状态。

### 11.2 稳定节点键

新增只读 NodeKey，不使用显示名称或 Code 作为界面状态键：

| 节点 | NodeKey |
| --- | --- |
| 根 | root |
| 通道 | channel:{ChannelId} |
| 设备 | device:{DeviceId} |
| 分组 | group:{DeviceId}:{GroupId} |
| 异常设备容器 | virtual:orphan-devices |

DevicePointTreeNodeViewModel 的 Name、SummaryText、计数等可更新属性不能再全部是构造后只读，否则无法复用节点实例。

### 11.3 页面状态对象

在 DevicePointManagementViewModel 内增加明确的状态快照：

~~~
DevicePointUiState
  SelectedNodeKey
  ExpandedNodeKeys
  SelectedPointId
  TopVisiblePointId
  TreeSearchText
  PointSearchText
  SortColumn
  SortDirection
~~~

TopVisiblePointId 比直接保存像素偏移更稳定。恢复时优先选中 SelectedPointId，再调用 DataGrid.ScrollIntoView；找不到时使用 TopVisiblePointId。

### 11.4 树集合合并

禁止每次调用 TreeNodes.Clear 后重新 new 所有节点。

建议增加以下职责：

- BuildDesiredTree：从当前 DeviceConfig、Groups、Points 生成轻量描述树。
- ReconcileTree：按 NodeKey 合并到现有 ObservableCollection。
- ReconcileChildren：更新、插入、移动、删除子节点，并复用同键实例。
- FindNodeByKey：恢复选择。
- ResolveSelectionFallback：目标被删除后的父级回退。

合并算法：

1. 对目标 Children 按期望顺序遍历。
2. 同键现有节点存在时，更新 Name、SummaryText、Count 和 IsVirtual。
3. 目标位置不一致时使用 ObservableCollection.Move。
4. 不存在时 Insert 新节点。
5. 递归合并其子级。
6. 从后向前删除不再存在的节点。
7. 不修改复用节点的 IsExpanded。

初次 LoadAsync 可以创建整棵树；之后的新增、编辑、移动、删除必须走 ReconcileTree。

### 11.5 展开状态绑定

DevicePointManagementView.axaml 使用节点状态到 TreeViewItem 的单向初始化绑定，并由视图接收 TreeViewItem 的 Expanded/Collapsed 路由事件写回节点状态。这样既保留默认 TreeViewItem 主题的可视模板，也必须证明：

- 用户手动展开后 ViewModel.IsExpanded 为 true。
- 用户手动收起后 ViewModel.IsExpanded 为 false。
- 集合合并不会覆盖该值。

搜索处理：

- 第一次进入树搜索时保存 ExpandedNodeKeys。
- 搜索期间只临时展开命中项祖先。
- 清空搜索后恢复搜索前集合。
- 搜索文字变化不得把所有节点永久设为展开。

### 11.6 点位集合合并

RefreshVisiblePoints 改为 ReconcileVisiblePoints：

1. 根据当前节点范围和 PointSearchText 计算目标点位列表。
2. 以 PointId 为唯一界面键。
3. 复用同 PointId 的 DevicePointRow，或让行对象支持 UpdateFrom。
4. 用 Insert、Move、Remove 最小更新 Points。
5. 按 SelectedPointId 恢复选择，不使用引用相等判断。
6. 只有选中点位不在当前筛选结果时才清除选择。

### 11.7 保存流程

SaveEntriesAsync 不应在成功后无条件 LoadAsync。建议改造为返回 DeviceConfigurationApplyResult，并接收成功后的选择意图：

~~~
SaveEntriesAsync(
  entries,
  groups,
  successText,
  UiSelectionIntent intent)
~~~

UiSelectionIntent 至少包含：

- PreferredNodeKey。
- PreferredPointId。
- DeletedNodeFallbackKey。

成功路径：

1. CaptureUiState。
2. 构造完全独立的候选 entries 和 groups。
3. 调用 ApplyPointsAsync。
4. 要求 applied.Ok 为 true 且 Snapshot 不为空。
5. AdoptApplied(applied.Snapshot.Points)。
6. 从返回快照更新 _allEntries 和 _allGroups。
7. RebuildDeviceFilters。
8. ReconcileTree。
9. ReconcileVisiblePoints。
10. 按 intent 优先、旧状态其次恢复选择和滚动。
11. 更新 ActiveRevisionText 和成功消息。

失败路径：

- 不调用 AdoptApplied。
- 不替换 _allEntries、_allGroups。
- 不重建树。
- 不改变选择和展开状态。
- 只显示后端返回的明确错误。

通道、设备、信号绑定应用成功后也使用同一 ApplySnapshotAndRestoreUi 方法，避免各入口再次出现全页重载。

## 12. 配置版本与运行时安全边界

“界面局部刷新”和“运行时局部应用”不是同一件事。

当前 DeviceConfigurationService.ApplyAsync 会：

1. 写入候选 Revision。
2. 停止旧运行时。
3. 创建并启动新运行时。
4. 提交 active.json。
5. 发布新的 ActiveRevision。

DeviceWritePipeline、SignalResolver 和 TestExecutionService 都依赖 ActiveRevision 判断点位对象、采样和试验记录是否过期。因此本轮必须遵守：

- 页面可以局部合并 UI 集合。
- 后端仍使用现有完整快照原子应用。
- 不得只改 active.json 而保留旧运行时版本。
- 不得仅修改 runtime.ActiveRevision 而让设备会话继续产生旧 Revision 样本。
- 不得为了减少界面闪动绕过活动试验锁、权限、引用校验或运行时切换。

分组理论上只是展示元数据，但当前 GroupId 位于 points.json 的完整版本中。若未来要做到“移动分组不重启设备运行时”，应另立任务：

1. 将分组定义及 PointId→GroupId 映射迁移到独立的展示配置。
2. 展示配置使用自己的版本和原子保存。
3. 运行时快照不包含展示分组。
4. 兼容读取旧 points.json 的 GroupId，并提供一次性迁移。
5. 证明写入、采样和试验记录的 ActiveRevision 语义不被破坏。

在上述设计和测试完成前，不实施“分组变更跳过运行时重载”。

## 13. 驱动能力与客户选项

点位编辑器的数据类型必须来自所属设备驱动的 IDeviceDriverDescriptor.SupportedDataTypes。

设备编辑器规则：

- 新建设备时只默认展示 IsImplemented=true 的驱动。
- 未实现驱动不作为普通客户的可选项。
- 若旧配置已使用未实现驱动，编辑时可显示为“未接入，仅可停用保存”，避免无法打开旧配置。
- 不允许把未实现驱动的设备启用并应用。
- 不允许自动回退为 Simulation。

当前只有 Simulation 可作为已验证运行时能力；Modbus RTU、Modbus TCP、S7 的描述器存在不等于真实通信已经实现。

## 14. 当前导入导出格式

设备点位模板已直接切换为唯一的 v5 固定中文格式，不保留旧模板解析分支：

- `DevicePointTemplateDefinition.Columns` 定义唯一的 9 列及其顺序。
- 导入器只接受固定中文表头；旧版、英文表头、增加单位或启用状态的文件直接拒绝。
- 导入预览仍是应用前的强制步骤，冲突按 PointId、设备归属、地址和 Code 规则校验。
- 当前页面按树节点生成模板范围；单设备范围可省略设备前缀，多设备范围必须填写设备前缀。
- 导入只合并文件中的新增/更新点位，文件未出现的其他设备点位保持不变。
- 点位模板不应用单位或点位启用状态；导入的新点位固定参与运行。
