## 1. 一页结论

本次优化采用“配置管理器工作台”方向：

```text
选择左侧层级对象
        ↓
查看右侧范围和状态
        ↓
通过属性窗口修改候选配置
        ↓
统一校验、预览变更
        ↓
保存并应用新配置版本
        ↓
验证运行状态和点位质量
```

核心层级固定为：

```text
全部设备 → 通信通道 → 设备 → 点位分组 → 右侧点位清单
```

其中：

- 通信通道负责 TCP、串口或仿真连接资源；
- 设备负责 PLC、控制器、仪表或从站身份；
- 点位分组只负责界面组织和筛选；
- 点位负责具体地址、数据类型、读写属性和工程换算；
- 点位配置修改不等于向现场设备写值；
- 所有配置修改必须经过统一服务校验和版本化应用；
- 活动试验期间禁止修改设备点位、通道和设备配置；
- 真实 Modbus、S7 等驱动未有现场证据时，界面只能显示“已登记/未验证”，不能显示为已连接或正式支持。

本方案分为四个首批界面和一个后续诊断界面：

| 编号 | 界面 | 首批级别 | 作用 |
|---|---|---|---|
| 1 | 设备点位总览 | P0 | 日常选择设备、查看点位、执行新增/编辑/删除/导入 |
| 2 | 点位属性编辑 | P0 | 修改地址、类型、权限、量程和说明 |
| 3 | 通道/设备属性 | P0 | 按通信资源和控制器身份分层配置 |
| 4 | Excel/CSV 导入预览 | P0 | 批量修改前校验、对比、解决冲突 |
| 5 | 点位测试与通信诊断 | P1 | 查看当前值、质量、时间戳和诊断结果 |

## 3. KEPServerEX 操作习惯提炼

### 3.1 需要借鉴的操作模式

KEPServerEX 官方配置界面把项目内容放在统一的 Project Tree 中，并提供节点级右键操作、属性编辑、复制、删除、保存和 Quick Client 入口。[官方界面导航](https://support.ptc.com/help/kepware/kepware_server/en/kepware/server/navigating-the-configuration.html)

需要借鉴到当前页面的不是品牌外观，而是以下行为：

| KEPServerEX 习惯 | 当前模板的对应设计 |
|---|---|
| 先选择树节点，再操作对象 | 先选择通道、设备或分组，再在右侧维护点位 |
| Channel → Device → Tag Group → Tag | 通信通道 → 设备 → 点位分组 → 点位 |
| 双击或 Properties 打开属性 | 双击点位、设备或通道打开对应编辑窗口 |
| 右键菜单按当前节点提供动作 | 动作矩阵按根、通道、设备、分组和点位行动态收敛 |
| Tag 属性集中编辑 | 点位编辑窗口集中编辑地址、类型、权限、换算和说明 |
| CSV 导出后批量编辑再导入 | 当前固定中文 Excel 模板、校验、预览、合并应用 |
| Quick Client 验证数据 | 后续增加点位测试和通信诊断入口 |
| 保存后项目生效 | 通过完整配置快照、版本切换和运行时重载生效 |

### 3.2 不直接照搬的内容

- 不新增“项目”“OPC 项目”顶层菜单；当前上位机本身已经是项目上下文；
- 不把 KEPServerEX 的英文内部字段直接暴露给客户；
- 不把 `PointId、DeviceId、ChannelId、Revision` 删除或改成显示字段；
- 不把点位分组当成通信路由；
- 不把配置修改按钮当成 PLC 写入按钮；
- 不把未实现的 Modbus/S7 驱动伪装成可用；
- 不默认支持动态 Tag、自动发现、自动生成 Tag 或第三方 KEPServer 项目同步；
- 不用完整替换导入静默覆盖当前目录，必须先显示变更和冲突。

### 3.3 KEPServerEX 官方字段与当前模板映射

| 官方字段 | 当前模板字段 | 实施规则 |
|---|---|---|
| Tag Name | 点位标签/点位名称 | 客户优先维护业务名称；内部编码继续保留 |
| Address | 地址 | 原样保存驱动地址，同时按设备驱动和型号校验 |
| Data Type | 数据类型/原始数据类型 | 只显示当前驱动支持的中文类型 |
| Client Access | 访问权限 | 只读、可写（普通）、可写（高风险） |
| Scan Rate | 设备配置中的采集周期 | 当前不在点位层重复填写 |
| Scaling | 量程换算开关和四项量程 | 四项完整时才启用线性换算 |
| Eng Units | 不配置工程单位 | 当前点位模板不保存工程单位；需要单位语义时由业务信号或驱动配置提供 |
| Description | 说明 | 用于用途、来源和现场备注 |
| Tag Group | 点位分组 | 只负责展示和筛选，不改变 I/O 路由 |
| Respect Data Type | 无直接对应 | 当前运行时始终按已配置类型解析 |
| Scaled Data Type | 无直接对应 | 当前没有独立工程数据类型，不伪造该能力 |
| Clamp Low/High | 暂不支持 | 不导入、不导出，避免配置看似生效但运行时无效 |
| Negate Value | 暂不支持 | 需要时另立驱动或业务逻辑任务 |

以上映射已在当前模板定义中存在，应继续保持单一来源：[DevicePointTemplateDefinition.cs](../src/XXX.TestBench.Core/Configuration/DevicePointTemplateDefinition.cs)。

## 4. 产品目标与非目标

### 4.1 产品目标

1. 客户能够按照“通道—设备—分组—点位”的自然层级找到目标点位；
2. 客户能够在一个属性窗口中完成点位修改并看到校验结果；
3. 客户能够清楚区分连接资源、设备身份和地址映射；
4. 批量导入不会静默覆盖、误绑定设备或绕过地址校验；
5. 保存失败时，当前生效配置、界面候选配置和运行时状态不混淆；
6. 设备点位页面在 1152×720 和高 DPI 下仍能正常使用；
7. 所有操作支持鼠标、键盘和明确的可见按钮；
8. 运行时状态显示真实质量、时间戳和连接状态，不以旧值冒充新采样；
9. 内部稳定身份和历史绑定保持兼容；
10. 后续可以替换或扩展真实驱动，而不重写点位页面。

### 4.2 本方案不做

- 不在本轮直接实现真实 Modbus RTU、Modbus TCP 或 Siemens S7 通信；
- 不把 KEPServerEX 作为当前程序的强制运行依赖；
- 不新增单独 OPC 项目管理页面；
- 不迁移现有试验项点、产品型号或参数管理页面；
- 不修改设备写入管线的安全门槛；
- 不在活动试验运行期间提供配置应用；
- 不以仿真读取证据宣称现场硬件或 UOS 支持；
- 不支持无限层级分组；首版只支持一层业务分组；
- 不以拖拽作为首版点位移动的必需操作；
- 不将所有 KEPServerEX 高级字段一次性加入客户界面。

## 6. 目标信息架构

### 6.1 页面主结构

```text
设备与点位
├─ 顶部页面工具栏
│  ├─ 当前配置状态
│  ├─ 新增
│  ├─ 导入/导出
│  ├─ 信号绑定
│  └─ 更多
├─ 左侧设备层级
│  └─ 全部设备
│     └─ 通信通道
│        └─ 设备
│           └─ 点位分组
└─ 右侧点位工作区
   ├─ 当前范围标题和状态
   ├─ 点位搜索、筛选、排序
   ├─ 点位表格
   └─ 当前点位详情/状态
```

### 6.2 客户术语

| 客户看到的名称 | 内部对象 | 客户是否填写编码 |
|---|---|---|
| 通信通道 | `ChannelEntry` | 默认不填写内部 Id；名称必填 |
| 设备 | `DeviceEntry` | 设备编码保留内部，必要时在工程详情显示 |
| 点位分组 | `PointGroupEntry` | 分组名称可编辑，编码内部维护 |
| 点位 | `PointEntry` | 点位名称、地址、类型、权限和说明 |
| 当前配置版本 | `Revision` | 只显示“已保存/待应用/应用失败”等业务状态 |

### 6.3 树构建规则

1. 根节点固定显示“全部设备”；
2. 每个有效通道只显示一次；
3. 设备只出现在其 `ChannelId` 对应的通道下；
4. 分组只出现在其 `DeviceId` 对应的设备下；
5. 默认分组 `DEFAULT` 不单独显示；
6. 分组节点显示点位数量，但不生成点位子节点；
7. 具体点位只在右侧清单显示；
8. 无有效通道的设备进入“未关联通道（需修复）”虚拟节点；
9. 虚拟异常节点只暴露修复入口，不允许新增分组或点位；
10. 树节点只显示业务名称、状态摘要和数量，不显示地址、内部 Id 或复杂协议参数。

### 7.2 顶部区域

必须保留：

- 页面标题“设备点位”；
- 当前配置状态；
- 当前范围点位数量；
- 可见的“新增”入口；
- 可见的“导入/导出”入口；
- 当前运行模式、连接状态和活动试验提示。

建议动作：

| 当前选择 | 顶部主按钮 |
|---|---|
| 全部设备 | 新增通道、导入/导出 |
| 通道 | 新增设备、导出 |
| 设备 | 新增点位、新增分组、导出 |
| 分组 | 新增点位、导出 |
| 点位行 | 编辑点位、更多 |

“更多”只承载低频动作，不承载客户必须发现的主要能力。

### 7.3 左侧树区域

- 标题：`设备层级`；
- 说明：`选择通道、设备或分组查看点位`；
- 搜索框：`搜索通道、设备或分组`；
- 节点摘要：名称、在线状态、设备数或点位数；
- 通道节点显示连接方式摘要；
- 设备节点显示驱动摘要、启用状态和点位数量；
- 分组节点显示点位数量；
- 右键、Shift+F10、菜单键和可见“新增”按钮执行同一动作集合；
- 节点展开状态、选中节点和滚动位置在保存后保留；
- 左树不显示地址、原始协议字符串、数据库主键和修订号。

### 7.4 右侧点位清单

默认列顺序：

| 顺序 | 列名 | 说明 |
|---|---|---|
| 1 | 点位名称 | 第二行显示所属设备名称 |
| 2 | 设备地址 | 设备驱动地址原文 |
| 3 | 数据类型 | 客户可读中文类型 |
| 4 | 访问权限 | 只读、可写（普通）、可写（高风险） |
| 5 | 操作 | 编辑 |

交互规则：

- 双击点位行打开编辑；
- Enter 打开编辑；
- 右键只显示编辑、移动分组、删除；
- Delete 不直接删除，必须进入确认流程；
- 搜索只刷新右侧清单，不重建左树；
- 表格排序稳定，同值时以 `PointId` 作为最终排序键；
- 选中行更新后按 `PointId` 恢复，不因刷新而跳到第一行；
- 地址、数据类型不作为可直接编辑的表格单元格，统一进入属性窗口校验。

### 7.5 状态与空状态

| 状态 | 页面显示 |
|---|---|

## 8. 界面二：点位属性编辑

### 8.1 打开方式

- 右侧点位行双击；
- 选中点位后按 Enter；
- 点位行右键选择“编辑点位”；
- 设备或分组范围点击“新增点位”。

### 8.2 窗口结构

窗口标题：

- 新增：`新增设备点位`；
- 编辑：`编辑设备点位`。

副标题显示业务路径：

```text
现场以太网 / S7-1500 控制柜 / 模拟量
```

分区：

1. 基本信息；
2. 地址与数据类型；
3. 采集与换算；
4. 写入安全；
5. 说明与高级信息。

### 8.3 字段定义

| 分区 | 字段 | 新增 | 编辑 | 规则 |
|---|---|---:|---:|---|
| 基本信息 | 所属路径 | 只读 | 只读 | 显示通道/设备/分组名称，不显示 Id |
| 基本信息 | 点位名称 | 必填 | 必填 | 使用客户业务名称 |
| 地址与类型 | 设备地址 | 必填 | 必填 | 按所属设备驱动校验 |
| 地址与类型 | 地址提示 | 可用 | 可用 | 展示当前驱动支持的地址格式和示例 |
| 地址与类型 | 数据类型 | 必填 | 必填 | 只显示当前驱动支持的类型 |

| 采集与换算 | 原始下限/上限 | 条件 | 条件 | 必须成对填写 |
| 采集与换算 | 工程下限/上限 | 条件 | 条件 | 必须成对填写 |
| 写入安全 | 访问权限 | 必填 | 必填 | 只读、可写（普通）、可写（高风险） |
| 说明 | 说明 | 可选 | 可选 | 点位用途、来源和现场备注 |

### 8.4 保存前校验

- 点位名称不能为空；
- 地址不能为空；
- 数据类型必须选择；
- 设备地址必须符合所属驱动和型号规则；
- 地址和数据类型组合必须可被当前驱动接受；
- 当前设备内不能存在重复规范地址；
- 只读点位不能选择高风险写入；
- 量程四项必须全部填写或全部为空；
- 原始下限不得大于原始上限；
- 工程下限不得大于工程上限；
- 上下限不能相等；
- 点位编辑不能偷偷改变所属设备；
- 点位编辑不能通过修改分组绕过地址重复检查；
- 当前有活动试验时，保存按钮禁用或保存后由统一服务拒绝。

### 8.5 内部字段处理

以下字段保留在候选模型和持久化中，但不作为普通客户输入：

- `PointId`；
- `Code`；
- `DeviceId`；
- `GroupId`；
- `Protocol` 内部值；
- `RawDataType`；
- `AddressDefinition`；
- `DecodeOptions`；
- `WritePolicy`；
- `Revision`。

编辑点位名称、说明、地址或类型时，除明确的迁移任务外，不生成新的 `PointId`。信号绑定和历史记录依赖稳定身份。

### 8.6 写入安全提示

点位属性编辑窗口固定显示：

```text
配置修改不会直接写入现场设备。
```

当选择“可写（普通）”或“可写（高风险）”时，补充解释其运行时含义。高风险点位的配置保存可以通过更高权限控制，但不在保存点位时主动执行写入。

## 9. 界面三：通道与设备属性

### 9.1 通道编辑

通道是连接资源所有者，对应当前 `ChannelEntry`。

字段分组：

| 分区 | 字段 | 规则 |
|---|---|---|
| 基本信息 | 通道名称 | 必填，同一配置内唯一 |
| 基本信息 | 连接方式 | TCP、串口、仿真；按已支持能力显示 |
| TCP | 主机地址、端口号 | 地址和端口必须合法 |
| 串口 | 串口、波特率、数据位、校验、停止位 | 参数必须完整且组合合法 |
| 仿真 | 仿真实例 | 明确不打开 TCP 或串口 |
| 时序 | 超时时间、重试次数 | 必须大于等于允许范围 |
| 状态 | 启用通道 | 停用后关联设备进入不可运行状态 |

界面说明：

```text
树中只显示通道名称，连接方式和连接参数在这里设置。
```

修改通道名称可能影响外部引用路径，因此保存前显示影响提示，并列出引用设备数量。

### 9.2 设备编辑

设备是目标控制器、PLC、仪表或从站，对应当前 `DeviceEntry`。

字段分组：

| 分区 | 字段 | 规则 |
|---|---|---|
| 基本信息 | 设备名称 | 必填 |
| 基本信息 | 所属通道 | 必填，必须选择有效通道 |
| 基本信息 | 设备驱动 | 只显示已注册驱动；未实现驱动显示不可应用状态 |
| 型号信息 | 厂商、型号、CPU 配置 | 按驱动能力显示 |
| 协议参数 | Modbus 站号等 | 仅相关驱动显示 |
| 采集 | 轮询周期 | 设备级配置，点位继承显示 |
| 质量 | 陈旧判定时间 | 必须大于采集周期 |
| 状态 | 启用设备 | 停用不删除点位和绑定 |

界面固定展示关系说明：

```text
通道负责连接资源
设备负责目标控制器
点位负责地址映射
```

### 9.3 设备/通道变更影响

保存设备或通道配置前，系统应计算影响范围：

- 受影响设备数量；
- 受影响点位数量；
- 是否改变驱动；
- 是否改变设备所属通道；
- 是否改变地址解释规则；
- 是否存在不兼容的点位类型或地址；
- 是否存在信号绑定；
- 是否存在活动试验。

改变设备身份或驱动时，不能保留未经重新校验的点位候选。必须重新验证地址和数据类型，失败则阻止应用。

官方文档也将 Device 作为具体 PLC、控制器或硬件节点，并通过设备属性配置设备 ID、扫描模式和驱动相关参数。[官方设备说明](https://support.ptc.com/help/kepware/kepware_server/en/kepware/server/what-is-a-device.html)

## 10. 界面四：Excel/CSV 导入预览

### 10.1 操作步骤

```text
选择文件 → 读取文件 → 固定表头校验 → 解析字段

        → 用户确认 → 统一配置服务应用
```

### 10.2 预览顶部摘要

至少显示：

| 摘要 | 含义 |
|---|---|
| 校验通过 | 文件格式、字段、引用和驱动预校验均通过的行 |
| 更新 | 与现有点位匹配并有配置差异的行 |
| 新增 | 当前配置中不存在的合法点位 |
| 冲突 | 地址重复、设备不存在、分组不存在或类型不兼容 |

### 10.3 预览表格

| 列 | 说明 |
|---|---|
| 行号 | 原文件行号，便于客户返回 Excel 修改 |
| 设备 | 所属设备名称 |
| 分组 | 所属分组名称 |
| 点位名称/标签 | 客户识别字段 |
| 地址 | 原始设备地址 |
| 数据类型 | 中文类型 |
| 访问权限 | 写入安全等级 |
| 变更类型 | 新增、更新、无变化、冲突 |
| 校验结果 | 通过、需确认、阻止 |
| 冲突说明 | 精确到字段和行号 |

### 10.4 匹配规则

匹配必须使用稳定、可解释的顺序：

1. 当前模板不接受 `PointId`、单位和点位启用状态列；
2. 按当前设备范围解析后的设备编码和点位编码匹配更新；
3. 同设备同规范地址重复时，直接冲突；
4. 跨设备同名不能仅按名称匹配；
5. 文件中未出现的现有点位默认保持不变；
6. 全部设备导入必须明确设备归属，不通过点表隐式创建设备；
7. 新导入或更新的点位固定参与运行，不能通过模板关闭。

### 10.5 应用按钮规则

- 存在阻止级冲突时，“确认应用”禁用；
- 仅存在需确认的高风险新增时，显示二次确认；
- 取消预览不写文件、不改变内存中的生效配置；
- 返回修改文件不关闭当前生效配置；
- 确认应用前显示“当前试验未运行”；
- 应用失败后保留预览结果、候选内容和失败原因；
- 应用成功后显示新生效版本的业务状态，不直接显示内部修订号。

### 10.6 模板边界

当前唯一模板为固定中文 9 列 v5：

```text
点位标签、地址、数据类型、访问权限、
原始下限、原始上限、工程下限、工程上限、说明
```

列名和顺序不能由客户任意修改。下载模板时根据当前设备、协议和驱动能力收窄提示和下拉选项。

## 12. 节点动作矩阵

| 当前对象 | 右侧显示 | 主动作 | 更多动作 | 禁止或限制 |
|---|---|---|---|---|
| 全部设备 | 全部有效点位 | 新增通道 | 导入、导出、刷新 | 不能直接新增设备、分组或点位 |
| 通信通道 | 通道下所有设备点位 | 新增设备 | 编辑通道、删除通道、导出、诊断 | 不能直接新增点位 |
| 设备 | 该设备全部点位 | 新增点位 | 新增分组、编辑设备、删除设备、导出、诊断 | 活动试验时禁止应用 |
| 点位分组 | 分组下点位 | 新增点位 | 编辑分组、删除分组、导出 | 删除需处理其中点位归属 |
| 点位行 | 当前点位 | 编辑点位 | 移动分组、删除点位、查看状态 | 不能直接更换设备 |
| 未关联通道 | 异常设备提示 | 无 | 编辑设备修复 | 禁止新增配置 |
| 停用设备 | 原有点位 | 无 | 编辑设备、查看点位 | 禁止新增或应用点位 |

删除规则：

- 删除通道前必须处理设备引用；
- 删除设备前必须处理点位、分组、信号绑定和运行时引用；
- 删除分组时默认保留点位，转入设备默认归属；
- 删除点位前显示点位名称、地址、设备和引用影响；
- 所有删除操作均需确认，失败时恢复原界面状态。

## 13. 状态、候选配置与应用流程

### 13.1 三种配置状态

```text
当前生效配置（Active）
        ↑ 原子切换
候选配置（Candidate）
        ↑ 编辑、导入、校验
用户界面草稿（Draft）
```

规则：

- 弹窗编辑只修改候选副本，不直接修改运行时对象；
- 页面关闭或取消时，草稿丢弃但生效配置不变；
- 导入预览只生成候选结果，不写入生效配置；
- 全部校验通过并确认后，才进入统一配置服务；
- 配置应用失败时，Candidate、Active 和 Runtime 状态必须可区分；
- 页面刷新不得把失败的候选内容伪装成已生效内容。

### 13.2 保存并应用顺序

```text
1. 捕获树选择、展开状态、表格选中行和搜索条件
2. 检查活动试验和配置应用互斥门
3. 克隆点位、分组、设备、通道和相关配置
4. 执行结构、引用、驱动、地址、类型、权限和量程校验
5. 生成候选完整快照和变更摘要
6. 写入新的配置版本目录
7. 校验文件、哈希和完整快照
8. 原子切换 active 指针
9. 重载或切换运行时会话
10. 丢弃旧代次迟到数据和取消中的旧请求
11. 更新页面状态、保留用户导航状态
12. 写入审计和结果信息
```

### 13.3 回滚规则

- 新版本写入失败：Active 不变；
- 哈希或完整性校验失败：Active 不变；
- 运行时重载失败：显示“配置已保存但运行时未成功应用”，不得显示完全正常；
- 运行时新会话初始化失败：保留旧版本或进入明确的故障状态，按现有快照策略恢复；
- 页面局部刷新失败：保留当前生效版本和用户候选内容；
- 任何失败都不能继续使用未经验证的新对象。

### 13.4 与当前页面状态保持一致

保存成功后必须保留：

- 左树展开节点；
- 当前树选择；
- 当前点位搜索；
- 当前排序字段和方向；
- 当前选中点位；
- 当前表格滚动位置；
- 当前模板范围。

## 14. 校验规则详细清单

### 14.1 文本与身份

- 名称必填且不能只包含空格；
- 名称不能包含换行和控制字符；
- 通道、设备、分组和点位在各自作用域内唯一；
- 修改显示名称不改变稳定 Id；
- 内部编码冲突必须阻止应用；
- 点位标签解析失败必须给出行号或字段位置。

### 14.2 层级引用

- 设备的 `ChannelId` 必须引用现有通道；
- 点位的 `DeviceId` 必须引用现有设备；
- 点位的 `GroupId` 必须引用同一设备下的分组；
- 分组不能引用其他设备；
- 不允许点位通过分组变更绕过设备归属检查；
- 未关联通道设备只允许修复，不允许新增运行配置。

### 14.3 驱动和地址

- 地址验证必须由所属设备的驱动描述器执行；
- 地址提示必须来自当前驱动或明确的兼容规则；
- 数据类型必须是当前驱动支持集合的成员；
- 地址和类型组合不支持时阻止保存；
- 地址规范化后再参与重复判断；
- 需要范围分析的多字节地址必须检查重叠；
- 可写点位地址重叠第一版直接拒绝；
- 只读地址重叠至少显示警告，并根据当前驱动能力决定是否阻止；
- 不允许用通用字符串规则替代 S7/Modbus 等驱动专用校验；
- 驱动已登记但未实现时，允许查看兼容配置但不允许应用为可运行硬件配置。

### 14.4 量程

- 四个量程值全部填写才启用；
- 任意一个缺失都按未配置处理或直接提示补全，不能半启用；
- 原始上下限不能相等；
- 工程上下限不能相等；
- 下限不能大于上限；
- 非数值类型不显示量程；
- 量程计算异常不能落盘为看似有效的配置。

### 14.5 写入权限

- 只读点位不能配置高风险等级；
- 可写点位必须经过驱动和设备能力校验；
- 启动、停止、复位和输出类业务点位默认建议高风险；
- 修改点位权限必须产生审计；
- 配置保存不触发设备写入；
- 运行时写入仍只经过 `DeviceWritePipeline`。

### 14.6 运行状态

- 活动试验期间禁止配置应用；
- 配置应用与试验启动共享互斥操作门；
- 通道、设备、点位状态分层显示；
- 初始无值为 Unknown；
- 读取失败为 Bad；
- 超过陈旧时间为 Stale；
- 不能以其他设备在线证明目标设备在线；
- 仿真状态不能显示为现场硬件在线。

## 15. 权限、审计与安全边界

### 15.1 权限矩阵

| 操作 | 操作员 | 维护人员 | 管理员 |
|---|---:|---:|---:|
| 查看设备树和点位 | 允许 | 允许 | 允许 |
| 查看地址和状态 | 允许 | 允许 | 允许 |
| 新增/编辑点位 | 按现有权限 | 允许 | 允许 |
| 编辑通道/设备 | 禁止或按授权 | 允许 | 允许 |
| 删除点位/分组 | 禁止或按授权 | 允许 | 允许 |
| 应用配置版本 | 禁止或按授权 | 允许 | 允许 |
| 修改高风险写入权限 | 禁止 | 需更高权限 | 允许 |
| 执行写入测试 | 禁止 | 明确授权 | 允许 |
| 查看完整审计 | 只读摘要 | 允许 | 允许 |

权限名称沿用当前系统权限目录，不另造一套独立登录和角色体系。

### 15.2 审计内容

配置变更至少记录：

- 用户和角色；
- 操作类型；
- 通道、设备、点位和分组稳定身份；
- 旧值和新值摘要；
- 原配置版本和新配置版本；
- 校验结果；
- 应用结果；
- 运行时重载结果；
- 失败原因；
- 高风险权限变化。

### 15.3 配置修改与设备写入分离

必须保持以下边界：

```text
编辑地址/类型/权限/量程
        ≠
向 PLC、仪表或 Modbus 从站写入值
```

配置应用可以导致运行时重新建立采集会话，但不能自动把点位当前值写入设备。

## 16. 视觉和交互规范

### 16.1 视觉基线

- 延续当前蓝白工业软件风格；
- 页面背景使用浅蓝灰，内容区使用白色；
- 主操作使用品牌蓝；
- 成功/在线使用绿色；
- 配置待应用使用蓝色或灰蓝色；
- 冲突/需确认使用琥珀色；
- 阻止级错误使用红色；
- 不使用大面积渐变、装饰插画和营销卡片；
- 不使用过度圆角；
- 不通过缩小字体解决空间不足。

### 16.2 布局和尺寸

- 左树初始宽度约 30%～36%；
- 右侧点位工作区约 64%～70%；
- 中间使用可拖动 `GridSplitter`；
- 左树最小宽度建议 240 px；
- 右侧工作区最小宽度建议 520 px；
- 点位弹窗默认约 720×620，可调整大小；
- 通道和设备弹窗保持可调整大小；
- 底部“取消/保存/应用”按钮固定可见；
- 高级量程区域可以内部滚动，但常用字段不应被隐藏在滚动底部；
- 1152×720、100% 缩放下完成常用操作无需连续滚动。

### 16.3 键盘和可访问性

- Tab 顺序符合从路径到字段再到操作按钮的顺序；
- Enter 编辑选中点位；
- Esc 取消弹窗；
- Shift+F10 或菜单键打开节点菜单；
- 删除必须有键盘可达的确认按钮；
- 状态不能只用颜色表达，必须同时显示文字；
- 搜索框支持清空；
- 表格选中状态在刷新后可恢复。

### 18.4 Headless 和人工 UI 验收

Headless 测试必须单独记录：

- 进程是否正常退出；
- 是否发生测试超时；
- 是否存在残留 `testhost`、Avalonia 应用或 IDE 锁定输出；
- 是否生成有效 TRX；
- 没有完整证据时标记为“未验证”，不标记为通过。

人工验收至少执行：

1. 展开多个通道和设备，修改一个点位，确认展开状态不丢失；
2. 编辑地址为非法格式，确认不能保存；
3. 修改只读点位为高风险，确认不能保存；
4. 修改设备采集周期，确认点位显示继承值；
5. 删除普通分组，确认点位不会被静默删除；
6. 导入一条更新、一条新增和一条重复地址，确认预览正确；
7. 在活动试验期间尝试应用，确认被阻止；
8. 配置应用失败，确认生效版本和运行时不被污染；
9. 停用设备，确认仍可查看点位但不能新增和应用；
10. 使用键盘完成搜索、编辑、取消和确认。

以下内容必须独立于软件测试记录：

- 真实 PLC/仪表型号和固件；

- 一个经现场允许的写入测试点；
- 地址手册和类型说明；

- UOS/Linux 目标环境；
- 真实 KEPServerEX 或 OPC 客户端联调。

缺少上述证据时，只能写“配置模型已登记”或“仿真验证完成”，不能写“现场通信已完成”。

## 19. 风险和处理策略

| 风险 | 影响 | 处理 |
|---|---|---|
| 当前工作区已有未提交改动 | 误覆盖用户工作 | 先记录状态，按文件审计，不做破坏性回退 |
| 通道/设备名称变化 | 外部点位路径或绑定受影响 | 保存前计算引用并提示，稳定 Id 不变 |
| 改变设备驱动 | 原地址和类型可能失效 | 重新校验，失败阻止应用 |
| Excel 批量修改误覆盖 | 大量点位错误 | 预览、差异、冲突和确认；不静默覆盖 |
| 设备配置和点位配置混淆 | 客户误改通信资源 | 分离通道、设备和点位窗口 |
| 配置修改触发设备写入 | 现场安全风险 | 配置和写入管线完全分离 |
| 运行时重载失败 | 页面显示与实际运行不一致 | 明确显示“已保存但未应用”，Active 不伪造成功 |
| Headless 卡死或输出锁定 | 测试结果不可信 | 清理残留进程并重新顺序执行，超时标记未验证 |
| 未实现驱动被客户选择 | 现场交付风险 | 驱动支持矩阵控制选项和状态 |
| 过度复刻 KEPServerEX | 产品边界失控 | 只借鉴操作习惯，不引入独立 OPC 项目和无证据能力 |
